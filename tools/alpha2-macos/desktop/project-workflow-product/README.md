# Current-project product derivation candidate

This directory is an independent candidate. The original r44 application, frozen current-project workflow and r54 UI bridge remain unchanged. It targets only the fixed current project; arbitrary directory import and model-paid calls are outside this change. Physical Finder interaction remains `not_run`.

The bridge's r54 evidence covers 26 contracts plus three real APFS/single-Profile Node child IPC scenarios. Those scenarios model the native dialog result; they do not establish an Electron panel or real confirmation dialog.

## Fixed integration points

1. Retain AppKit/controller and controller/Electron lifecycle fd3. Add a separate owned fd4 between the exact Electron child and the already owned business child. The broker relays bounded bytes only. A fresh private nonce, actual PROGRAM SHA and acquired generation bind the channel. No HTTP mutation method or renderer approval token is added.
2. Derive the existing host owner/business host and launcher from exact frozen bytes. Pass the private binding outside public business input. The host factory obtains its bridge from the one existing controlled Profile/controller/project, never another store.
3. Derive the controlled profile plugin using the proven project-workflow project factory/lifecycle. Only its private service can create the bridge. The official agent tools retain their current authority and cannot approve a plan.
4. Add an independent host client UI plugin in the existing settings section. It calls four preload intents; all displayed diff content is text. A completed DOM render marks the exact review presented; Electron main owns `showMessageBox`, binds its result to the current window/document/review, and the host alone creates and consumes approval.
5. Existing Profile overlays require an explicit old-to-new, exact-SHA CAS migration under the existing launch lease/native helper. Accept only pinned old or already-new bytes; refuse unknown content. Keep PROFILE, source, P2 memory and budget unchanged. No fresh-store workaround.
6. Close admission/revoke pending dialogs first. Preserve the original API/parser drain and original startup blocked-owner recovery. Workflow closure drains the same controller before the original Profile closes. A channel EOF alone never releases an owner. Pending main confirmation and host work enter quit inspection.

## Fixed candidate manifest impact

Keep PROGRAM schema4 and its validated Contents root. Replace its business entry with the derived standalone; replace the controller runtime at its fixed role so it imports the derived launcher. Bind the changed final ASAR and signed inner executable. Preserve the existing 58 runtime paths and add three frozen bridge files, seven frozen workflow files (including preview.mjs and READONLY-ORIGIN.json) and eight product runtime files, for exactly 76. `EXPORT-MAP.json` and `package-inputs.mjs` enumerate these paths. The root assembler updates BOOTSTRAP closure, compiles the outer embedded manifest hash and signs/restores/inventories the result.

ASAR: replace only pinned `lib/main.js` and `lib/preload-app.cjs`; add `lib/project-workflow-product/endpoint.mjs` and five frozen modules under `lib/project-workflow-ui`. Host: add one three-file client plugin. Static client delivery uses existing Loader; mutation uses only owned IPC. Neither the existing five-method HTTP lifecycle API nor the original renderer root is widened.

`applyProjectUi({applicationRoot,evidenceRoot,asarPath})` is build-only. All paths must be real descendants of RUNNER_TEMP; evidenceRoot is fresh and outside the app. The app's parent must contain the exact PROJECT-DRAFT.json object specified by EXPORT-MAP.json. The helper verifies original r44 PROGRAM/ASAR and inner signature, applies exactly eight ASAR and three host changes, preserves all other ASAR entries, updates ASAR integrity and signs the inner app. It writes RESULT.json. A pass covers that operation only: final PROGRAM/BOOTSTRAP/outer signature and restored inventory belong to the root assembler.

## Evidence progression

`prepare-baseline.mjs` replays captured main → workspace → welcome → product → bare-import rewrite, checking exact r44 main/preload/renderer hashes. It writes small derived bytes and origin records to an explicitly fresh D:/RUNNER_TEMP root, without editing an app. `baseline.test.mjs` executes the actual preload and actual child host owner to record missing feature REDs, while confirming cross-origin/subframe denial and HTTP mutation rejection. Failed tests retain exact normal child cleanup receipts.

The first original-r44 RED has five definitions: three pass and two fail for the absent preload/owned-host feature. Candidate contracts have 16 definitions: relay three, exact ASAR derivation two, actual Node child fd4 one, endpoint three, overlay CAS three, client registration one, and source/runtime closure three. They require Node `--experimental-vm-modules`, plus SEP_PROJECT_PRODUCT_BASELINE pointing to the prepared small baseline directory. The client registration test is not a real browser DOM test. The Node child test is not an Electron fd4 test. Windows/POSIX results cannot certify the final macOS package.

Files beginning `native-`, `derive-native.mjs`, and `ax-capability.m` are separate test/operator work. They are excluded from the product build freeze and installed runtime. The read-only AX capability probe uses Apple's AXIsProcessTrusted without requesting permission or changing TCC. Its Boolean reports that process only, not confirmation completion: https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted.

Next acceptance must prove simultaneous real Electron fd3/fd4, actual renderer/preload/main routing, unchanged source and same Profile, native dialog cancellation and accepted result binding, stale navigation refusal, close/quit-pending inspection, restored inventory, and exact normal child exit. Programmatic native dialog interaction must be labeled automated; it does not prove physical interaction. Any unavailable GUI automation is reported separately, not replaced by a monkeypatched `showMessageBox` result.
