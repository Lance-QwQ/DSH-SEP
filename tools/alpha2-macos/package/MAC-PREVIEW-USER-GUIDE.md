# DSH SEP macOS ARM64 隔离预览说明

此文档随完整 Mac 安装器制作过程维护。安装器尚在集成验证，不能把本文当作公开发布或所有 Mac 均可使用的证明。

当前 r71 安装器已经完成构建、签名、归档恢复及完整下载核验。归档为 `DSH-SEP-macOS-Alpha2-installer-preview.zip`，692,789,908 字节，SHA-256 为 `59550c42943c2b01a2bf770174d00d792304a5599f87387596ff99df8b0d49f1`。r72 将验证原字节安装器启闭、独立测试入口的真实按钮／确认框安装，以及已安装应用的两轮启动；完整安装闭环尚未通过验收。

当前 r61 应用仍有一个已复现的问题：保留待审计划后重启，业务 Runtime 初始化会被计划选择门禁阻断，导致项目审阅界面也无法正常启动。r70 的第一轮通过、第二轮失败均保留；修复正在独立派生候选中验证，尚未进入 r71 安装器内的应用。旧 r44／r61 包不会因源码修复自动获得新能力。

本轮固定应用基线为 DSH 0.2.1-alpha.2 与 SEP 的 Mac 派生组合。已执行的原生证据来自 macOS 15.7.9（24G830）、ARM64 的独立测试虚拟机。Intel、其他 macOS 版本、物理鼠标与键盘操作、Developer ID 签名及 Apple 公证、真实私人资料接续和付费模型运行仍不在已认证范围内。

## 安装与数据位置

安装器只处理当前系统账户的 `~/Applications/DSH SEP.app`。账户主目录由系统账户记录确定，不接受通过 `HOME` 或命令行另指定安装目标。数据使用独立的 `~/Library/Application Support/DSH SEP/alpha2-mac-finder-preview`，安装事务记录位于 `~/Library/Application Support/DSH SEP Installer`。这些目录不应与官方 DSH 共享。

目前验证的是首次安装与受控恢复流程，不是覆盖任意已有程序的通用升级器。目标已有程序、来源不符或事务状态无法核验时，安装会拒绝；不要通过删除锁或修改事务文件强行继续。

窗口会先列出安装目标、数据位置、文件数量和计划哈希。点击 Install 后还需要确认该具体计划；取消审阅不会安装程序。成功提交后，Open DSH SEP 是单独操作。启动派发成功与应用健康检查通过是两个不同状态。

## 工作区与受控修改

本版采用受控工作副本。当前项目入口针对已绑定的单个项目；任意目录选择与自动纳管不在本轮范围内。项目页面展示当前项目、来源与副本状态，修改经过审阅和确认后提交为新的受管代次。原始导入目录保持不变，向外部来源导出尚未纳入本轮认证。项目管理授权与模型文件工具权限分开；模型不能以普通工具调用替代用户确认。关闭后恢复同一项目时，仍需原来的 P2 数据域权威与删除依据。项目页面整条操作链的验收状态仍以对应原生回执为准，不能从应用启动通过推断。

当前完整应用的固定 Profile 未开放普通 Shell、任务子进程或任意 MCP 接入；独立沙箱组件的测试不代表这些入口已在应用中启用。此预览不承诺任意第三方进程族均能成功运行或清理。发生收尾不明时保留隔离和阻断，不能把超时、窗口关闭或测试虚拟机销毁当作业务已经结束。

## 退出与异常

应用隐藏后可由系统启动入口重新打开；正常关闭要等待所属宿主和资源收尾。安装器在已接收的操作执行期间不会另行启动关闭请求，收到关闭回执后还会等待真实子进程退出与输出收尾。无法确认时保留窗口和阻断状态。

遇到 blocked 时保留当前诊断和事务资料。恢复只处理可核验的本程序事务，不会凭一个目录名或旧 PID 认定进程属于自己，也不承诺自动恢复任意损坏状态。

## 已有证据与当前限制

- r61 应用已完成装配、签名、归档恢复与完整下载核验；r64 对该固定包完成三轮 LaunchServices 启动、隐藏观察、同代重开和正常退出。
- r64 完整安装资源与真实控制器的预览、取消、列表和正常关闭通过；该测试没有点击安装确认。
- r68 关闭与退出的 8 项原生行为、固定安装目标打开的 7 项测试通过；前者使用合成控制器，后者使用已签名的短时合成应用。该阶段尚未完成完整生产安装器的构建、原字节启闭和真实 UI 安装验证。
- r71 补齐了完整生产安装器的构建、签名、归档恢复和下载核验。它不将 r68 的模块测试扩展为用户安装闭环通过；r72 的原字节启闭、真实安装及安装后运行仍待验。
- 安装器原生 UI 的模块测试、通信测试，与完整原字节安装器的最终用户操作证据分开记录。程序化按钮操作不等于物理输入认证。
- 当前签名为测试用 ad-hoc 签名，不能替代 Developer ID／公证，也不构成防止同账户恶意重签的安全边界。不提供关闭 Gatekeeper 或修改 TCC 的步骤。

最终制品的准确哈希、构建版本与尚未完成的验证以同代结果清单为准。Windows 日常程序不随本轮 Mac 测试更新。
