# Current application revalidation operators

These operators are a new evidence generation after the macOS low-priority review. They do not rewrite r44/r61/r74 receipts or frozen manifests. They require **real Darwin arm64**; no platform substitution is supported.

`application-environment.mjs R44_RESTORE OUTPUT` verifies the fixed r44 package inventory and PROGRAM, then writes `ENV.json` with the actual host, capture, native tree/attachment helpers, and parser fixture. The caller may use these paths for native tests. The host manifest is resolved with `createRequire(hostRoot + '/package.json').resolve('@deepseek-ai/dsh/package.json')`; its version must be Alpha.2.

`application-verify.mjs fixed R44_RESTORE MAC_SOURCE OUTPUT` validates the current source with those real native dependencies. It runs 41 existing definitions: 8 pending Loader/restart cases, 22 document contracts, 7 combined vision/Loader cases, 3 native document/context cases, and 1 standalone case. The first document group intentionally substitutes the parser service; the other groups use the real packaged parser. LLM adapters are synthetic and no paid provider is called. Each group must terminate normally with the exact expected TAP totals and zero failures, skips or cancellations. An immutable source inventory, 84 runtime hashes, package hash and logs bind the result.

`application-build.mjs R44_RESTORE MAC_SOURCE ASAR_MODULE OUTPUT NATIVE_VERIFICATION` requires that current native receipt, source inventory and r44 program to agree. It invokes the existing `package/assemble-pending-application.mjs`, which copies the current 84 runtime files, rebuilds PROGRAM/BOOTSTRAP, compiles the outer AppKit bootstrap, ad-hoc signs, archives, restores and verifies the new application. Its original `RESULT.json` shape is retained. A separate `OUTPUT-REVALIDATION.json` binds this generation to native evidence. This is a new artifact generation identified by hashes; it is not a release/version announcement. The existing assembler's bundle version and archive filename are retained for compatibility with its exact derivative contract.

`application-verify.mjs built OUTPUT MAC_SOURCE POST_OUTPUT` then verifies the generated inventory and that all 84 installed runtime bytes equal the current source mapping before running the same 41 definitions. The tests load the current source through the official Loader; equality with the installed runtime is checked before and after. This is **not** a claim that the test files execute inside AppKit/Electron. Two executions still represent 41 unique definitions, not 82 distinct tests.

Each output must be a new child of the canonical `RUNNER_TEMP`; source must be the checked-out operator source. Neither the old carrier nor source may change. These operators never install into the daily profile, mount real private user data, publish, or use a user's credentials. `runOwnedCommand` has deadlines and records cleanup of its command; this is not a global audit of arbitrary process descendants. Physical desktop interaction, existing private-data continuation, Developer ID/notarization, and other macOS/architecture coverage are separate evidence.

The package assembler only succeeds after its own actual native build/signature/restore commands succeed. Portable tests of the operator's 84-row and TAP contracts cannot establish native success. `application-contract.test.mjs` contains 9 such portable definitions. Native results remain `not_run` until the dedicated Mac job completes.

See `application-job.yml` for commands. The root workflow must insert the separately maintained core native regression step after reading ENV.json and before building. Follow-up installer work must pin the new assembly RESULT, revalidation receipt, post-build native receipt, inventory and zip after independently retrieving them; old r74 installer pins are not valid for this generation.
