# Native installer application composition

This is the next composition stage. It does not replace the frozen UI, admission, private protocol or transport. No application product has been assembled by this directory yet.

Production `main` accepts argc 1 only. It creates `NSApplication`, invokes the compiled-manifest `SEPInstallerVerifyMainBundle`, constructs `SEPInstallerPipeTransport` from that returned configuration, then constructs `SEPInstallerUI` and its application delegate. Failed admission or failed pre-launch validation must not start an owner. A started but unconfirmed owner remains in a visible blocked application; it is not terminated to make an installer exit test green.

The application menu contains an actual Quit item targeting the installer delegate, not an unconditional terminate action. The item and `applicationShouldTerminate:` route through the existing window-close contract. Accepted work continues with its window visible; idle close requests a single controller close. `NSTerminateNow` is allowed only after `UI.resourcesReleased` becomes true. A same-window `NSWindowWillCloseNotification` requests final termination only after this exact gate; unrelated windows and ordering-out do not count. Closing the last window alone does not terminate the process. The private transport retains the owner until actual stdout/exit evidence has been delivered.

The separate `FixedApplicationOpener` obtains the target from the current account record (`getpwuid(geteuid())`), never HOME, renderer input or an installer argument: `~/Applications/DSH SEP.app`. It compares the committed URL to that exact target, rejects aliases, verifies the installed PROGRAM and BOOTSTRAP bytes against the admitted payload values, and verifies the actual application signature before requesting `NSWorkspace.openApplication`. The reply is only “dispatch accepted”, not an assertion that the application is healthy. It does not run an update, invoke a shell or open a replacement target automatically.

The first native test stage will exercise real AppKit menu/window/delegate calls with the already tested UI and a synthetic owner, preserving real NSAlert behavior. This establishes command routing and release gates, not actual installation. A separate signed synthetic application at the fixed ephemeral CI account target will exercise opener refusal and dispatch. Native product composition with the actual controller, full payload, restored bundle and real account installer is a later fixed-input integration stage owned by the root task.

Planned fixed lifecycle definitions: actual Quit item exists and routes through the delegate; idle Cmd-Q requests one close; accepted install refuses parallel close/termination; duplicate quit does not duplicate close; close receipt alone refuses termination; normal exit plus receipt permits termination; abnormal exit stays blocked; unrelated window close cannot trigger termination. The test-only termination recorder will be compile-time gated and absent from the production binary. It must not be used to claim actual process exit.

Before final application assembly, the transport's post-admission role replacement checks and the private transport/native tests must pass. App signing and final INSTALLER/PROGRAM byte bindings are generated by the root assembler only after all resources are frozen. This stage does not modify the daily version or publish a release.
