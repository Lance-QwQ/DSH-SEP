# Alpha.2 macOS 原生基础阶段

本阶段已恢复真实 macOS CI，并完成原生所有者/租约、预算账本与 App Sandbox 写入隔离可行性验证。**完整 macOS SEP 尚未完成；本阶段没有构建或运行完整 DSH Alpha.2 应用，没有生成可用的 Full/Only 安装包。**

环境是 GitHub 托管的 macOS 15 arm64 虚拟机。本机找回的历史材料来自同类真实 Mac CI：旧 DSH 0.1.7-rc.2 的 9 轮桌面证据，不是 Alpha.2 认证。已搜索的 Windows PATH、虚拟机注册目录、活动进程与 D 盘镜像中未找到可直接启动的本地 Mac 入口；不据此断言其他位置不存在。

## 失败样本与复核修正

首次 Sandbox 试验在无保护对照中因 Objective-C 将布尔表达式编码为数字 `0` 而触发严格类型断言；当时尚未开始带沙箱测试。`control.json` 证明对照可改写原文件。已改为明确的 `@YES/@NO`，原失败工件与日志保留，后续正例与之分开。

独立源码复核确认捕获模块与固定提交相符、现有通过回执没有发现假阳性问题。按复核补充了编译/签名失败的阶段日志、预算测试清理的有界退出确认，并从固定 Git 对象取源。最后复跑覆盖修正后的完整输入。清理回执不等同于全系统句柄或全部后代零残留证明。

## 下一阶段的实现边界

1. 新增 macOS APFS 安全树访问 helper，使用目录 fd 与 `openat/fstatat` 逐级校验、不跟随链接；验证大小写/Unicode、目录替换、硬链接和大小限制。Linux 的 `/proc/self/fd`＋ext4 代码不可直接搬用。
2. 建立生产用签名 worker 与有界 IPC，只传递本次工作副本；原库、账本、治理记录及提交权限留在控制器。App Sandbox 的同一应用容器不天然区分项目，需另行证明跨项目、跨事务和迟到进程隔离。
3. 在上述基础上接入受管代次、计划哈希、提交、删除依据和恢复事务；复用现有规则前重新验证各崩溃窗口。当前没有开放 Mac 完整受保护 Profile。
4. 接入实际 Alpha.2 Loader、P2 三域、记忆/RAG、附件、视觉、上下文和预算设置；再验证真实桌面启动、Dock/菜单栏、关闭后台、重新打开和退出。
5. 评测、Accessibility/Computer Use、TCC 和更新安装分别认证；最后制作 Full/Only 包并执行多轮实包装卸与恢复。

官方 Alpha.2 的 Darwin 子进程实现没有持久进程范围所有者。主进程或进程组退出不能证明所有逃逸后代已退出；不能确认时保持 `blocked/cleanup-unconfirmed`，不得释放事务写入准入或宣称零残留。当前 owner-posix 使用秒级 `ps lstart`，高速 PID 复用仍未覆盖。
