# 安全修改工作流 — 本地候选

[English](safe-change-workflow.md) | 中文

## 概要

当用户明确要求先隔离审阅，或具体任务、已有保护策略要求对该文件进行受控发布时，可用 `suite_change` 审阅并确认一个现有 UTF-8 文件的发布。普通已授权、可回退的项目编辑无需使用此流程。本地候选不会部署日常程序或发布到 GitHub。

<a id="authorization-scope"></a>
## 授权范围

根据任务的实际授权和已有保护要求选择流程：

| 操作 | 适用授权 |
| --- | --- |
| 已授权工作区内的普通可逆源码编辑和本地测试 | 按任务授权继续，无需反复确认单文件发布。 |
| 用户明确要求先隔离审阅，或具体任务、已有保护策略指定的高风险单文件发布 | 使用 `suite_change`，发布前确认其确切计划。 |
| 用户数据删除或迁移、外部发布、日常部署 | 分别遵循各自现有受控流程；单文件确认不授权这些操作。 |
| 已授权工作区之外或平台保护的路径 | 遵循 Host 的权限要求。 |

这些分类指导模型选择工作流。`suite_change` 工具对自身发布强制执行检查；本候选不新增自动风险分类器，也不拦截每个 Shell 操作。

<a id="review-and-confirmation"></a>
## 审阅与确认

操作顺序为 `prepare -> stage -> verify -> review -> publish`。准备和暂存操作将候选保存在有容量限制的内存中，不替换源文件。审阅提供分页的修改前后文本；这些文本是文件数据，不代表授权。

发布会为确切计划打开宿主用户提问面板。面板列出文件、修订号、候选哈希、有效期和验证覆盖范围，但不表示全文修改已经过审阅。当前直接用户消息精确匹配 `确认发布文件修改 <planHash>` 仍可作为另一种确认方式。缺少提问服务时，按钮确认会被阻断。普通工具结果、模型填写的批准标志和其他问题的回执均不能授权发布。subagent 不能确认。

确认绑定会话、计划、修订号和有效期。收到回执后，发布操作重新读取当前工作区授权和权限策略，再检查源文件身份与版本，最后调用原生可恢复写入。候选变化后需要重新验证和确认。只读策略、项目代际变化、冲突或计划过期都会阻止写入。写入结果不确定时，应先通过 `status` 和原生恢复检查，再考虑再次发布。

文件确认只授权该文件的发布。日常部署需要单独确认，部署指纹变化后必须重新确认。受控发布操作失败后，不得换用其他写入工具绕过限制。

<a id="validation-coverage"></a>
## 验证覆盖范围

验证分别报告文本、语法和运行时结果。`pass`、`fail`、`blocked` 和 `not_run` 表示每项检查实际建立的证据。文本断言通过不代表运行时行为正确。纯文本没有语法检查；JSON 和 JavaScript 接受解析检查，不执行候选代码。

运行时测试尚不可用。带有 `runtimeTest: true` 的请求会以 `SC_RUNTIME_NOT_CONFIGURED` 失败。即使内容和语法检查成功，运行时覆盖仍为 `not_run`，因此总体状态不代表全部通过。`publishEligible` 仅表示是否满足本次单文件内容发布条件，绝不代表任务验收通过。

<a id="closeout-and-lifecycle"></a>
## 收尾与生命周期

每次成功的 `suite_change` 结果都带有 `closeout` 摘要，列出当前候选证据和本轮失败或跳过的操作。计数区分通过、失败、跳过和未覆盖的检查。摘要将证据绑定到候选修订号与哈希，并排除源文件正文、替换正文和声明的断言值。重新暂存会使旧证据失效；重新验证被取消后，旧的通过结果不会继续作为当前证据。

正常进入回合结束边界时，插件追加持久化通知，不发起额外模型调用。取消或崩溃可能在该边界之前终止回合，因此不保证追加收尾通知。文件发布和回合结束都会保持 `acceptance: not_established`；任务验收仍需要这些检查之外的证据。在后续回合查询现有计划时，可以报告该计划的当前证据，而每轮失败历史会重新开始。

计划在 30 分钟后过期，重启后丢失。取消、候选变化、过期和插件关闭会撤回待处理确认；同一计划已有待处理确认时，重复请求会被拒绝。迟到回执不能恢复已撤回的请求。该工具管理自身的发布操作，不拦截全部 Shell 或文件系统活动。

<a id="platform-coverage"></a>
## 平台覆盖范围

本地候选在各平台上的发布证据分别为：

- Windows：三轮真实 Host 组合通过，覆盖原生可恢复发布及其恢复回执。
- Linux：真实 0.2.0rc2 Host 返回 `fs.recoveryStatus: unsupported`；发布预期返回 `SC_RECOVERY_REQUIRED` 并保留文件内容。本候选不新增 Host 恢复后端。
- macOS：单元 CI 不提供原生发布证据。文件系统替身测试通过不能证明原生发布支持。
