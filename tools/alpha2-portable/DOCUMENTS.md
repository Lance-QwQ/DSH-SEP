## 有效删除范围

- 原有 `suite_document_delete` 的 preview / confirm / resume / status 接线到真实 SEP 文档管理器及 P2 三域治理，沿用精确计划哈希和当轮直接用户确认。
- 删除当前项目的 RAG 当前正文、历史文档归档、受管三域备份/暂存中的相关内容，并清理 Linux 受控工作区所有历史代次中该逻辑路径的文件。所有未提交候选副本一并清理，旧候选计划失效，预览明确显示副本数量及此副作用。
- 原始导入目录保留。`deleteSource:true` 明确拒绝，错误码 `SEP_LINUX_ORIGINAL_SOURCE_RETAINED`，不会把它悄悄解释为删除工作副本。预览列出 `imported_original_source` 为排除项；后续回执的 retained 仅指原始导入文件。
- 原生聊天历史、外部导出、系统备份及未登记副本不属于本入口删除范围。没有宣称安全擦除物理磁盘、SSD 或已释放内存；删除后若旧正文仍在当前模型上下文，原生会话上下文的处置也不在本入口内。

## 持久化顺序与恢复

1. 预览生成不含正文的计划，绑定逻辑项目/来源、实际受控副本清单和哈希；计划文件 fsync 后同步目录。
2. 确认时在同一受控视图队列中重新核对计划；P2 先可靠落盘业务意图与永久删除依据，再治理三域正文。
3. 受控副本控制器在 FULL synchronous SQLite 中保存删除意图及仅含元数据的 before 清单，然后删除已核验文件、同步其父目录并清理候选副本。
4. 所有代次验证完成后，以一个 SQLite 事务更新代次清单、失效旧计划、增加业务序号、提交删除完成记录。P2 受管备份/暂存清理及回执随后收尾；未能确认完成时不能宣称 deleted。

P2 删除依据在可恢复的三个数据域之外；受控工作区的删除记录也不随普通代次恢复回退。每次访问都在 **P2 原有访问租约**内核验依据，绑定当前项目，不能拿另一项目同名文件的标记删除本项目。恢复代次不恢复已删除正文；已删除路径重新生成以及已知旧正文被改名复制，均被拒绝。重新准入是独立的未来授权机制，本轮没有实现。

进程在任意已测删除阶段崩溃后，启动先进入 P2 专用删除恢复入口，核验不含正文的原计划，再完成受控副本删除。只接受已知删除前缀；幸存文件新增或内容改变不能伪装成部分删除。计划、依据或身份无法核验时保持停写，不从旧正文副本“恢复”来消除错误。其他普通 P2 未完成事务不会因启用删除恢复而获准运行。

同进程删除未收尾时，新工作可能被恢复门禁阻断；修复底层存储问题后，通过可信控制器重新绑定依据或重启接续。模型不能调用代次提交、恢复或依据绑定能力，不能以重试绕过门禁。受控目录以单独宿主控制器及 Bubblewrap 命名空间保护；不承诺防御恶意同 UID 宿主代码、管理员或恶意本机原生插件。

当前保守界限：一次清单最多 128 个代次、256 个事务；沿用每棵树 1024 项、32 MiB 总量、单文件 4 MiB 等既有界限。超出、未知副本、链接或身份不明均拒绝，不能据此无限扩展清理范围。
