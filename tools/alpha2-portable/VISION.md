## 已实现的接线

1. 图像附件必须先于 LLM 冷启动，使用私有的 `<memory>/.suite-attachments`，与项目源目录、RAG、账本分离。目录须为真实 ext4 路径、当前用户所有、无组/其他用户权限；拒绝符号链接、多硬链接和重叠目录，包括 `..private` 这样的子目录。
2. 默认业务组合不启用视觉，也不挂载该附件域。启用时必须同时指定 `vision: { enabled: true, allowUpload: true }`；这代表部署级明确允许上传，不能推断为每次调用都会再次弹出确认框。
3. `suite_vision` 从当前受控代次/候选读取图片，保留稳定的逻辑项目边界；原始导入文件不被修改。图像须符合官方 PNG/JPEG/WebP/GIF 校验及 4 MiB 输入限额，使用真实 Sharp/libvips 解码、官方归一化与请求变体。
4. 原有模型图像能力和路由定价两项证明均保留；请求经原有 P1、会话、单轮及共享账本约束，不新增免费通道，不清零账本。结果标明模型解释不可信、来源哈希、图像尺寸及留存策略。
5. 工具入口、原生附件方法和模型入口均检查准入。未激活、根关闭、子代理写入/视觉调用、路径越界、权限异常会拒绝。已接收的原生图像操作计入根生命周期；请求变体的后台任务须实际收尾后才能释放相应令牌。独立附件租约持续到附件载具真正处置完成。
6. 付费请求取消或迟到时保留保守的 `unknown` 预留；有界关闭可返回 `blocked` 并保留所有权，不将超时当作操作未执行。

通用原生**非图像文件附件**会创建硬链接别名，尚未适配本轮单链接清除策略。因此 `saveFile/saveFileStream/readFileStream/fileHostPath` 明确返回 `SEP_LINUX_FILE_ATTACHMENT_UNSUPPORTED`，不先生成无法纳管的副本。数字 PDF、DOCX、文本仍走既有受控工作区及 `suite_extract`，不属于该原生图像域。不得据此宣称所有附件功能均已完成。

## 留存、删除与恢复契约

图像的归一化副本、请求变体及失败产生的域内临时文件都保留到明确的离线清除；**没有自动 TTL**。关闭窗口、结束会话、删除 RAG 文档均不会自动清除附件。文档被永久排除后，既有原生图像引用仍可读取，直到附件域独立清除。

清除仅提供给停止实例后的可信操作员，未注册为模型工具。须同时取得 P2 与附件独立租约，生成正文为空的完整文件清单，再使用精确计划哈希确认。身份/哈希/目录或内容变化使旧计划失效；原始导入文件、RAG 和账本不被删除。已有会话中的附件引用可能因此无法读取。

清除顺序：确认新鲜清单 → 持久化删除意图并 fsync 文件和目录 → 逐项核验身份/内容后 unlink 并 fsync 所属目录 → 核验零剩余 → 持久化完成回执并 fsync 目录 → 释放租约。`onEvent` 是可信控制层的无正文审计切点，CLI 和模型均不能提供该回调。

意图存在而未完成时冷启动拒绝，不能直接恢复上传。操作员重新生成剩余副本清单并再次精确确认；新完成回执对账旧意图。测试真实终止了三个切点的进程：意图落盘、首次删除、完成回执落盘。该证据覆盖进程死亡，不等同于真实断电或磁盘故障。

附件冷启动还复用既有 P2 文档删除接续入口，避免新增附件服务让前一阶段的中断恢复卡在 `P2_RECOVERY_REQUIRED`。原有文档删除依据、受控代次清除及原始源文件保留规则不变。

可信 Linux 操作示例（使用实际内存库路径及 `owner.json` 内的项目 UUID；实例须已正常退出）：

```sh
umask 077
node linux-attachment-cli.mjs plan /real/private/memory PROJECT_UUID > /real/private/purge-plan.json
# 人工审阅清单、影响与 planHash 后，显式执行：
node linux-attachment-cli.mjs apply /real/private/memory PROJECT_UUID /real/private/purge-plan.json EXACT_PLAN_HASH
```

计划文件必须是当前用户拥有的私有、单链接、非符号链接文件，最大 1 MiB；CLI 只输出 JSON，失败返回码 2，仅回传白名单错误码。清除清单上限仍为 2000 个文件、总计 256 MiB、单文件 20 MiB；Linux 私有树扫描额外限 4096 个条目与 16 层。超过容量会停止，需可信维护，不能宣称无限留存能力。

## 验证与失败归因

最终封存源码：`/opt/dsh-sep-cross-platform/alpha2-portable-vision-final-r16`。`linux-evidence/RESULT.json` 绑定 49 个输入文件、最终 TAP、各阶段日志、冻结 SEP 叶子、官方桌面输入和实际图像原生组件哈希。补充复核 r17 的 22 项属于相同定义的重复，不增加 116 的分母。

| 新增定义 | 数量 | 核心证据 |
| --- | ---: | --- |
| 视觉组合 | 8 | 当前候选、真实附件/请求字节、结算、能力/定价拒绝、默认关闭、激活与子代理限制、畸形图像、输出/金额限额、迟到取消与权限变化 |
| 附件域 | 7 | 私有权限、两个租约、精确清除、原生引用门禁、拒绝非图像别名、冷启动及跨项目绑定、点前缀目录重叠 |
| 附件恢复 | 7 | 三个真实 SIGKILL 切点、跨重启/文档删除后的引用、陈旧计划/别名/外项目拒绝、真实 CLI、与 P2 文档恢复组合 |

历史失败保持原始 TAP/日志：

- r1：视觉仍被旧能力门禁拒绝；r3：停止后附件域宽权限未被原有维护器拒绝。r3 的首次 mkdir 权限样本受 umask 影响，后来显式 chmod 才构成有效宽权限样本；不把该首例当作独立权限缺陷证据。
- r4：同一 mkdir 夹具权限未实际放宽；r5：计划激活传入了额外字段、误将官方工具的安全说明当作保留了机器码，以及图像写入会自动收紧权限，暴露了必须在工具入口提前核验的时点缺口。
- r7：无中断审计切点/无离线 CLI 的失败基线；r9：真实原生附件引用绕过激活、通用文件生成未治理硬链接。均已新增实现并验证。
- r10：测试处置 Context 后再读取已撤下的绑定，属夹具错误；r11：冷启动未允许现有 P2 删除接续，已修；r15：点前缀子目录被错误当成父目录路径，已修。
- r13 桌面：测试模型与原生模型重复注册。r14 桌面：移除付费提供方后原生欢迎页按设计显示，探针未点击“稍后设置”，60 秒截止；不能据此宣称产品无法打开。最终 r16 实际点击欢迎页控件，未伪造凭据或登录状态。两个失败样本的 `forcedCleanup=true` 保留。
- r17 的补充 22 项复核通过；证据采集器随后因误用旧 Sharp `lib/index.js` 路径失败。实际 0.35.5 入口为 `dist/index.cjs`，修正后在新目录重做机械封存，不改动已测试的 49 个输入或重算功能测试分母。

最终两轮桌面使用官方主程序原字节，仅前置一个测试观察器 import；真实 Loader、Connection、记忆/预算页面、图像 codec 与账本均执行。每轮视觉合成请求 1 次、结算 1 项，关闭隐藏/重开/正常退出通过，宿主和 Electron exit 0，`forcedCleanup=false`，退出后离线计划能取得两个租约且仍能盘点两个图像副本。

最终资源审计只覆盖专用发行版当前 UID 下可识别的测试、桌面与沙箱命令。先前 `blocked` 样本由夹具释放迟到请求后完成处置；两次失败桌面由各自 runner 的精确 finally 清理取得最终零残留。最终零残留不会倒推那些当场回执已成功释放。
