## 强隔离原型的契约

用户确认采用“使用更强隔离，验证后再开放写入”。实测 flock 只对合作方生效；没有用它替代 Windows deny-write 句柄。

`linux-isolation.mjs` 调用发行版 Bubblewrap。上游明确说明保护取决于调用参数，本组件不是仅安装 Bubblewrap 即获得安全保障：[上游安全说明](https://github.com/containers/bubblewrap#sandbox-security)。本轮参数指定独立 user/pid/network/ipc/uts 命名空间、只读系统与源目录、空私有可写工作目录、去除 capabilities、禁止新 user namespace、no_new_privs、清空环境、独立会话、父进程死亡收尾。目录通过继承 FD 绑定，源路径不会在子进程派发时重新解析。只暴露 `/usr`、必要库路径、沙箱自己的 `/proc`、最小 `/dev`、`/tmp`、`/source` 与 `/work`。

要求 Linux x64/native ext4、当前用户所有的真实目录、0700 私有空工作目录，以及匹配 SHA-256 的非 setuid、非组/全局可写二进制。不接受已有工作目录内容，避免预置硬链接绕过源目录只读视图。命令不经 Shell 拼接，输出上限 64 KiB，截止最多 10 秒，杀死且等待自己创建的沙箱后才返回。

发行版组件：Ubuntu noble-updates `bubblewrap 0.9.0-1ubuntu0.3`，只解包在本轮 D 盘目录，没有系统安装或运行包脚本。deb SHA-256 与 APT 包元数据一致：`2461f1beee9cb04c8942739fe1a2b37e7b7c2a3d518f0779dc75f9245baa3094`。二进制：`e318903862396f96de3df57264e0158682b952fd3fb53ac23d876413e7b30f71`。

测试设置 `SEP_BWRAP_SHA256` 为上述二进制哈希，运行 `isolation.test.mjs`。该原型只支持合成、全新工作目录，没有自动把结果写回源目录。外部同用户任意代码、内核漏洞、CPU/内存/磁盘配额和项目发布事务不在已验证范围内。
