# DSH SEP 原生记忆与会话预算设置插件

当前候选适配 **DSH 0.1.7-rc.2 / Cordis 4.0.4 / React 18.3.1**。沿用 `@deepseek-ai/dsh-client-ui-settings-memory` 组件及现有 `sep-memory-settings` 插件实例；组件原固定版本标识保留，具体变更由 SEP 总体候选版本与文件指纹绑定。

默认宿主入口为 `lib/index.js`；客户端入口为 `@deepseek-ai/dsh-client-ui-settings-memory/client`（`lib/client.js`）。同一插件现在在原生设置中并列提供 **“记忆增强”**（`sep-memory`）与 **“会话预算”**（`sep-budget`）。无需再安装新插件，也不增加会话模式。Cordis 配置入口保持 `enabled: true`、`requestTimeoutMs: 120000`；超时可设置为 1000–300000 毫秒。

## 会话预算

默认单会话累计金额护栏为 **100 元**。用户可修改默认值，或从本 Profile 的根会话列表选择一个窗口并设置独立上限。输入范围 0.01–1,000,000 元，最多两位小数。默认变更影响无独立上限的会话；保存独立上限后，该会话不随默认变化。本版没有清零、重置消费或删除账本入口。

页面展示本地累计计入金额、已结算估算、未结预留和剩余额度。**它们不是 DeepSeek 账户余额，也不是提供方账单。** 无法归属的旧消费只计共享总账。结果未知的请求保持预留，不因取消等待或修改设置释放。会话身份使用持久化的根会话 ID，列表不需要读取对话正文或私人标题。

**会话上限、共享总预算和单轮任务上限独立生效。** 当前共享总预算 100 元与单轮 5 元限制保留；将会话上限提高至 200 元也可能被共享剩余额度或单轮限制拦截。修改上限不会清除原消费；低于已计入金额时，后续新请求被限制，已经发出的请求仍需结算。归属于根会话的子代理计入同一会话护栏。

所有保存携带读取时的修订号。冲突、超时、断线或响应丢失后只重新读取，不自动重复提交。默认变更后重新读取所选会话的修订号。读取失败隐藏旧值；套件或 P1 不可用时显示不可用，不伪造 0 元余额。关闭页面会取消本页等待并清理计时器；取消等待不等于服务端没有提交。

## 协议与边界

记忆路线保持 `/api/sep-memory/list|get|update`。新增 `/api/sep-budget/list|get|update|updateDefault`，使用原生 `client-request/server-response` 信封、16 KiB 请求限制及既有本机桌面/loopback 身份门禁；服务委托给 `suiteEnhancements.budgetSettings`，宿主负责会话授权、比较后提交和账本互斥。此设置服务不注册为模型工具，也不调用模型。

远端 Web 访问不在支持范围。独立预算页面通过 `settings.section` 原生插槽注册，随插件卸载一起移除；保留原记忆页生命周期和功能。

## 构建与验证

本轮源码与产物均位于真实 D 盘隔离目录，宿主和客户端分别严格 TypeScript 编译，浏览器产物使用当前 DSH `clientBundle` 构建。`build.mjs` 引用当前固定本地构建工具；`node_modules` 只复用既有依赖，不修改日常安装。

`tests/` 包含预算 API 校验、Host 传输权限、真实 React DOM 交互及构建后原生入口检查；另有真实 SEP 不可用服务跨 Host 与客户端的组合。覆盖默认值、窗口选择、修订冲突、超时不重复提交、旧值隐藏、跨会话错配、金额输入、消费保留和卸载收尾。此处测试没有付费模型调用，不等于日常安装已切换或完整桌面视觉验收。总体候选的集成和部署结论以其绑定报告为准。

## 历史说明

此前 README 中 `0.1.5-rc.2 / Cordis 4.0.2` 是原记忆设置插件的历史来源；`0.1.7-rc.1` 是上一阶段固定宿主。它们不是本候选的实际运行目标。原记忆功能仍按项目保存自动学习和自动引用偏好，不读取记忆正文，关闭偏好不删除记忆。


### 2026-09-28 账本完整性提示
- 同源宿主桥和客户端只额外公开 BUDGET_LEDGER_MISSING、BUDGET_LEDGER_CHANGED 两个稳定错误码，不显示底层异常正文。
- 预算账本缺失时，设置页隐藏未能重新确认的金额，并提示恢复和核验原账本；保留刷新入口，没有清零或自动重建按钮。
- 账本在操作期间变化时，明确说明写入被拒绝；沿用已有读取确认流程，不自动重复保存。
- 本变更依赖 SEP 预算层的对应拒绝规则。账本与全部协调证据同时消失、完整旧账本被外部替换均不属于此提示组件能够修复的范围。
