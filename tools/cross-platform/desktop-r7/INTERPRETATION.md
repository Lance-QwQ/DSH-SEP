# r7 验证边界与历史解释

## 范围保持

- Windows 日常程序、其工作区、用户插件、真实账本和凭据均未修改。Windows 只运行 D 盘临时夹具的 9 项打包回归和 1 项环境保持检查；4 项 POSIX 测试在 Windows 明确跳过，在原生 Linux/macOS 验证。
- GitHub 仅使用 `codex/sep-cross-platform-20260929` 测试分支。没有 main 合并或 Release。
- 本轮实际启动的是 r4 固定应用构建、r6 安装器派生的空白 Full 实例，加上单独下载并按 npm 锁定摘要核验的 Electron 44.0.0。启动器的 POSIX 临时路径修正纳入新 bootstrap。**这不是完整桌面发行安装包已经交付的证明。**
- 真实模型调用为零；仅用明确无效的合成凭据让空白测试页面进入工作界面，不读取私人 API key。

2. Linux attempt-02：三轮旧断言通过，但截图只有 `Loading plugins…`，**只采信窗口/宿主生命周期证据，不采信完整工作界面就绪**。原 RESULT 保持原字节，不改写成更强结论。
3. Linux attempt-03：单独补跑三轮，复用 attempt-02 的合成安装。固定断言要求启动画面消失、工作框架已挂载、至少四个按钮存在；三轮全部通过。每轮正常退出后检查本轮宿主不再存在；最终命令路径审计没有本轮 Electron/桌面宿主残留。
4. macOS CI 36546441172：测试夹具使用 `/var` 别名触发 `PAYLOAD_ROOT_ALIAS`，尚未运行应用。已将夹具规范化到真实路径，保留失败日志。
5. macOS CI 36547013617：使用旧页面断言；不得单凭此运行通过声称工作界面完成渲染。
6. macOS CI 36547418095：采用收紧后的页面断言；最终结论以其结束状态与下载证据为准。

三轮中的单项检查数是执行记录，不等于新增问题类型；不计算性能开销，不把补跑与首次失败合并为无失败的首轮结果。

## 本轮修复

POSIX Electron 的临时目录改为系统临时目录内、以 uid 和安装路径摘要区分的短目录，权限必须为 0700，拒绝符号链接或错误所有者/权限。持久数据仍留在原实例目录；Windows 环境保持原行为。该小型 IPC/临时目录不承载安装包或构建副本；在本地 WSL 中仍位于 D 盘承载的专用发行版。

## 仍未验收

- 完整 Electron 载荷的 Full / Only 分发封装与安装器集成、上游 Linux 打包目标。
- Linux 托盘入口：当前代码仅在 Windows 创建原生托盘；Linux 关闭后可由二次启动恢复，不据此宣称托盘已经适配。
- 人工鼠标拖动、任务栏/托盘真实点击、macOS 辅助功能/屏幕录制等 TCC 授权。程序化 setBounds 只是 API 记录，不是人工拖动证据。
- macOS SEP 应用签名、公证及公开发行准入。验证官方 Electron 归档不等于签名 SEP 完整应用。
- 任意官方 DSH 安装形态的 SEP-only、官方 DSH 与 SEP 的真实桌面并存、自装插件及非空 RAG 数据迁移。

现有固定验收要求不降低；本轮不能把上述项目标成 pass。
