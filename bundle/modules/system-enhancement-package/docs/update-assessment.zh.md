# DSH 更新后台评估

[English](update-assessment.md) | 中文

本文说明 SEP 的可选后台评估服务。原生设置中的“更新适配评估”默认关闭，需要既有 P1 预算服务。开启即允许后台产生付费模型请求。该服务不会安装更新、准备发布版本或修改插件代码。

## 触发与证据

桌面端沿用启动时及每三小时一次的更新发现。发现带有 release ID 的官方 DSH 新版本后，提交公开发布说明及当前插件静态报告。关闭评估时仍可发现更新，但不发出评估模型请求。开启后处理当前尚未尝试的报告；失败或中断的报告需要用户明确点击重试。

服务使用配置的 P1 模型，先分析，再单独请求证据复核。复核可见首次结果，但必须重新对照同一证据。两次回答一致不构成执行证据。静态不兼容插件或报告中的冲突会阻止总体评估通过。所有结果保留 `installable: false`；API、schema、宿主接口与运行时验证均未执行。安装器不会将模型批准作为准入证据。

模型只接收有长度限制的公开发布信息、包名、版本、静态判定及原因码。相同公开插件信息合并为带实例数的分组。本地路径、配置值、凭证、对话、记忆和项目文件均不发送。所有插件实例仍通过报告和指纹在本地绑定。发布说明和模型文本均视为不可信输入，模型没有工具权限。输入过大时拒绝评估，不静默省略插件后宣称兼容：最多 10,000 个实例、600,000 字节规范化本地证据、90,000 字节模型请求数据。

## 费用与取消

两个阶段均使用既有共享预算账本及请求结算逻辑，每次尝试使用一个后台任务身份，不创建用户 Session。分析与证据复核共用该次尝试的 P1 `taskLimitCny` 配置额度，每次请求发出前同时检查共享上限。后续绑定更低上限会减少额度，但不会提高该任务已记录的额度。设置页分开展示已报告的输入/输出 token、计算费用估算和结果未知的预留。没有报告 usage 时显示“尚未报告”，不声称消耗为零。估算不是提供方账单；账务读取失败时不展示无法确认的金额。

关闭后停止后续请求并取消本地等待。已发出的请求仍可能收费，返回的 usage 仍须结算。结果未知时保留预留。手动重试创建新的后台任务，是一次新的、可能收费的尝试；此前消费仍保留在共享账本中。重新打开设置、重启宿主或重复发现均不会自动重试。

## 持久化与恢复

`update-assessment.sqlite` 位于配置的预算账本旁。SQLite `user_version=1` 保存开关/当前任务设置及按固定输入绑定的运行记录。事务认领发生在模型请求前。任务键绑定发布内容、当前 Host/SEP/配置/报告指纹及模型策略。证据变化产生另一项评估；旧响应不能覆盖新尝试。新记录还将规范化的原始发现输入与绑定模型策略后的输入分别保存。开启、发现与重试均从原始输入和当前模型策略生成任务键，因此仅切换开关或重复发现不会产生另一次尝试。既有预算账本格式不变。

崩溃后保留已认领的尝试。超过截止时间后，读取显示中断、阻塞，需要明确重试恢复。在 Node 事件循环仍能响应的条件下，阶段截止时间也限制无响应提供方的等待。不能保证远端已发请求停止。存储失败会让评估不可用，但不会关闭套件既有预算保护。不要通过删除评估数据库或预算账本重置失败尝试或消费。

缺少原始发现输入的旧记录显示为阻塞、中断，原因码为 `ASSESSMENT_REDISCOVERY_REQUIRED`，原有分析、复核及用量仍可查看。开启只保存开关，普通重试不可用。请通过已有的检查官方更新入口重新获取发现证据，无需重置数据库或账本。发现得到相同任务键时只补充缺失元数据，不重跑已尝试的评估；证据或策略变化形成不同任务键时才创建新评估。

## 宿主与客户端集成

设置插件在 `/api/sep-assessment/` 下提供需认证的本地 `get`、`update`、`observe`、`retry` 路由。只有受控桌面载体能提交发现证据。原生设置客户端可读取状态、改变开关和请求重试。这些路由和服务不是 Agent 工具。结果使用 `pass`、`fail`、`blocked`、`not_run`；运行中、已发现、中断属于独立生命周期阶段。

核心、服务及桌面投影测试使用注入的模型回答。受控宿主健康检查使用耗尽的合成预算和空白隔离 Profile。这些检查不证明真实模型输出质量、原生桌面视觉正确性或跨平台安装就绪。
