# DSH SEP 0.2.0-beta.2 — Windows Beta 测试版

本版保持 DSH 0.1.7-rc.2，修复 SEP 的 P1 策略与宿主原生图片通道不兼容的问题。仅声明 Windows x64 适配范围。SEP 原创部分采用 MIT，第三方保留各自许可。

## 修复内容

原生 `read_image` 可以成功返回已存储图片，但旧 P1 在下一次模型请求时会无条件抛出 `P1_IMAGE_NOT_ALLOWED`。后续纯文字消息仍携带历史图片，因此也可能重复失败。本版允许通过已许可模型的明确图像能力、附件服务和原生图像计量检查的图片进入宿主原有处理链路。

每次保留图片出现均按 1024 图像 tokens 的保守上限加对应描述文字预留费用，相同附件重复出现也分别预留预算；实际 usage 用于结算。已卸载图片只计文字占位，不恢复图片。无图像能力或能力不明的模型明确拒绝保留图片；缺失或异常计量拒绝请求，不取消预算保护。

新增能力查询等待期间，用户取消或插件停用会阻止后续预留与派发。图像身份、格式归一化、编码字节和数量限制继续由原生附件服务及适配器执行。能力/计量拒绝与该等待期间取消不产生预算预留；在预留之后发生的附件或传输失败仍保守保留预留，预留本身不证明已经发生网络请求。

运行时程序清单相对公开 Beta.1 共 7 项变化：P1 适配、新图像预算模块、套件 README，以及 4 项 Beta.2 版本绑定。没有清空数据、覆盖用户插件或重新执行已有任务的变更。

## 验证与边界

本轮修复候选完成 37 项定向检查：27 项 P1 图像/预算单元检查、4 项真实 Loader / Agent / `read_image` / 附件 / 官方适配器 / JSONL 组合检查，以及 6 项原预算回归。旧版和修复版保留对应失败与成功证据。新的公开 Full / Only / Update / Source 包另作分发验证，结果范围见 [VERIFICATION.md](VERIFICATION.md)，不把旧包结果冒充新包结果。

组合检查使用本地 HTTP 录制响应，原生 Files 路径收到合成 404 后走真实 inline fallback。它验证请求与记录链路，不证明真实在线模型的视觉理解质量，也不证明 Files 在线上传、复用已通过。固定正例重复三轮，不扩大为全部图片格式、尺寸或所有多模态场景。

Beta.1 的原生 GUI、另一台 Windows 和既有广泛回归属于历史证据，本次不宣称已全部重新执行。兼容性盘点中的未逐项验证记录表示证据尚不充分，不能据此认定相同数量的故障或用户插件；数量取决于具体安装。

仍保留的已知限制包括：更新查询可能显示 `metadata-unavailable`；部分 SEP 策略异常在宿主结构化错误字段中仍归为 `UNKNOWN`，其消息保留具体错误码。本版没有扩展修复这两项。已有私人任务未自动续跑；是否继续由用户在确认当前工作状态后决定。

## 安装与更新

新用户选 Full；Only 需要受支持的精确官方 npm DSH rc.2 来源。两者在新目录创建独立实例，不自动复制私人数据、插件配置或密钥。差分 Update 只接受 [UPDATE-SCOPE.md](UPDATE-SCOPE.md) 中的公开 Beta.1 指纹，不能仅凭版本号相同强制安装。

下载后比对 `SHA256SUMS.txt`。完整源码与测试随 Source 提供；源码包不包含私人 Git 历史、真实 Key 或私人会话。
