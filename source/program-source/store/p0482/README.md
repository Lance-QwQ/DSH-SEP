# DSH SEP 记忆增强设置插件

本插件在 DSH 原生设置页增加“记忆增强”分区，不新增会话模式。项目列表由宿主已经配置的项目注册表提供；页面展示项目名称及路径，所有修改按注册 ID 授权。该插件不读取记忆正文。

“自动记忆增强”主开关由已保存的自动学习、自动引用两项派生：任一项开启则主开关开启。主开关开启会开启两项，关闭会暂停两项。两项始终可分别调整，包括仅开启其中一项。界面分别显示已保存偏好、宿主配置限制及运行状态；不把偏好开启视为运行健康。

关闭不会删除记忆，也不会停止手动查询、编辑、删除与到期治理。已经进入当前对话的内容不撤回。作用域为所选项目，变更从下一次记忆操作生效；正在运行的记忆处理可能使保存等待。

页面在打开、项目切换、连接代次变化及点击“刷新”时读取宿主状态，明确显示为上次读取状态。修改提交携带已读两项作为比较条件；冲突后重新读取而不覆盖其他写者。等待期间保留已确认的开关值并禁用编辑。超时、断线或回复丢失时只重新读取，不自动重发修改；重新读取也失败则隐藏旧开关，直到用户刷新成功。

## 插件组合

rc.2 宿主在原生 Fetch 分派中注册 `/api/sep-memory/list|get|update`，使用原生 client-request/server-response 信封和 16 KiB 请求限制。Web 入口要求 HTTP(S) 与实际 loopback 绑定，并沿用上游认证、Host/Origin 检查；Electron 的 `dsh-app` 请求仅在官方 Desktop Host 明确提供所属私有管道标记时接受，不能因没有 Web 服务而自动放行。处理器委托 `suiteEnhancements.memorySettings.list/get/update`，由套件负责项目授权、比较后保存、存储治理与取消。套件缺失时返回不可用状态。浏览器通过 Connection 的 `/api` RPC 调用，在 `settings.section` 注册可卸载分区，随 connection.generation 变化刷新。显示错误只接受固定诊断码，不返回异常正文或栈。

宿主和浏览器入口均支持以下 Cordis 配置：

```yaml
enabled: true
requestTimeoutMs: 120000
```

`requestTimeoutMs` 是每次 RPC 等待上限，可配置 1000–300000 毫秒。它不证明超时修改未提交。通道只用于本机设置管理，未声明远程访问支持。本候选使用 `@deepseek-ai/cordis@4.0.2` 和 DSH `0.1.5-rc.2` 客户端依赖，运行库和样式通过新版原生客户端加载器共享。

## 构建与验证

候选源码与测试放在独立目录，`node_modules` 指向本轮隔离、固定版本的依赖。`build.mjs` 先分别严格检查宿主/浏览器 TypeScript，再使用 rc.2 自带 `clientBundle` 构建原生闭包模块和受插件生命周期管理的 CSS Modules。本轮配套宿主改动包含 Desktop Host 私有管道标记；原有四种模式保留，日常部署尚未切换。

组件测试覆盖组合开关、作用域、保存等待、并发冲突、未知保存结果、超时、晚到响应、项目切换和卸载；RPC 测试覆盖协议校验与敏感错误清理，原生 slot 测试覆盖延迟声明、语言切换和卸载重挂。正式部署证据应以套件的实包安装和真实浏览器组合报告为准。

## Model experience

本插件不增加模型工具或提示，不调用模型。模型工具 `suite_memory_auto_settings` 与界面使用同一套持久化偏好；模型提炼和检索能力仍由 DSH SEP 记忆模块提供。
