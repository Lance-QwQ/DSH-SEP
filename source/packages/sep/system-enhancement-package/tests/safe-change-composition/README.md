# SEP safe-change workflow composition

English | [中文](README.zh.md)

This Node 24 test boots the shipping `sep-safe-change` plugin through a real Loader YAML composition. The explicit installed Host is pinned by `host-lock.json` for Windows x64; another reviewed platform or candidate uses an explicit absolute `SEP_WORKFLOW_HOST_LOCK` pointing to its own lock, without rewriting the committed Windows graph. Each lock supplies `platform`, `arch`, `nodeMajor`, `graphSha256`, and dependency entries; every selected Host dependency file and dependency link is verified before use. The test stages current SEP source into a fresh directory under the explicit evidence root. Windows work uses the designated D: output root; WSL work uses its approved ext4 output root stored on D:. It does not load daily-profile configuration or call a paid model.

The composition uses the real AgentLoop, tools pipeline, native local filesystem recovery, recovery HTTP Host plugin, user-questions service, and JSONL session persistence. Only the LLM adapter and the user answer event are deterministic substitutes. The answer substitute exercises the same question-service reply fields as the UI; this is not a browser visual or physical-click test.

Set `SEP_WORKFLOW_HOST` to the exact reviewed installed `program` directory and `SEP_WORKFLOW_EVIDENCE_ROOT` to the approved task output directory. Windows uses `D:\AIData\ProjectWork\DSH\sep-workflow-closeout`; WSL uses `/opt/dsh-sep-cross-platform/sep-workflow-closeout` on the D:-backed distro. Set `TEMP`/`TMP` (or `TMPDIR` on POSIX) to that output root's `tmp` directory. Host, lock, and output paths must be absolute and not aliases. Run `node --test` with the absolute path to `composition.test.mjs`. `SEP_WORKFLOW_SOURCE` optionally names an explicit SEP source directory; otherwise the test stages its package's current `src` directory.

The three scenarios cover trusted approval without a second typed phrase, rejection without publication, current content/syntax/runtime evidence in tool results and a non-waking closeout notice, failed checks with a completed turn, and a subsequent ordinary turn. Each scenario reopens its persisted session and compares every event against the live record. Windows successful publication separately reads the changed and untouched files and locates the native recovery mutation receipt. On Linux and macOS, approval instead must fail with `SC_RECOVERY_REQUIRED` and leave both files unchanged because this Host implements recoverable publication only on Windows x64 NTFS. The rejection and failed-check scenarios run on each platform. The deliberate model self-report of all tests passing cannot change the closeout evidence.

Each run retains `source-binding.json`, test-only Loader configuration, native recovery data, `observed.json`, and `durable-session.json` in a uniquely named evidence directory. Failed runs are retained for diagnosis. The test owns and closes its recovery server and Cordis context. No generated output is deleted in bulk and no daily program is modified.

The complementary [top-level SDK snapshot](../../../../../snapshots/sdk/sep-safe-change-closeout/snapshot.yml) starts the shipped `dsh --profile sdk` through the public SDK. Its authored, keyless session requests `runtimeTest: true`, records the real `SC_RUNTIME_NOT_CONFIGURED` tool refusal and deterministic closeout notice, then completes a separate ordinary turn. The session, assembled SEP system prompt, and tool schemas are committed replay inputs and expected outputs. The driver asserts exactly three model responses across the two turns, so the closeout cannot add a model request. Only this scenario disables platform shell/skill catalogs and dynamic runtime context to keep its headers portable; the real SEP, recovery, file-policy, Loader and session services remain active. Successful approval and native recoverable publication remain covered by the composition above.

From the repository root with Node 24 and installed workspace dependencies, set the approved D: `TEMP`/`TMP` (or POSIX `TMPDIR`), set `DSH_SNAPSHOT=replay`, and run `node node_modules/vitest/vitest.mjs run --config vitest.snapshot.config.ts snapshots/sdk/sdk.snapshot.ts -t sep-safe-change-closeout`. `DSH_SNAPSHOT=refresh` rewrites only this scenario's goldens using its authored replay responses and never needs an API key. Run `scripts/session-snapshot-corpus.corpus.ts` with the same Vitest config to check corpus ownership and fixture invariants. The SDK driver escapes `{{cwd}}` as JSON string content when hydrating Windows paths; no product runtime or shared normalization rule is changed.
