# 更新过滤设置

本页说明 2026-10-07 过滤行为。本次 `v0.2.1-beta.2` 安装包包含该设置；旧 `v0.2.1-beta.1` 资产保留封存字节。旧用户请按[离线升级说明](OFFLINE-UPGRADE-BETA2.md)升级。历史部署以 [验证摘要](UPDATE-FILTER-VERIFICATION.json) 区分。SEP 保持 Beta，DSH 宿主保持 0.2.0-rc.2。

## 设置入口与通道

打开“设置 → 通用设置 → 更新过滤强度”。一个选择同时控制 DSH 与 SEP 的更新发现，并在重启后保留。

| 选项 | 可发现的更新通道 |
|---|---|
| 弱 | Alpha、Beta、RC、正式版 |
| 中 | Beta、RC、正式版，过滤 Alpha |
| 强（默认） | RC、正式版 |

首次安装及没有保存过该设置的已有安装都采用强。需要继续收到 SEP Beta 更新时，选择中或弱；强会按用户设定过滤 Beta。只考虑高于当前已安装产品版本的更新。草稿、非法版本、未知预发布命名和无法核验的发布信息仍不能成为可安装候选，“弱”不等于执行任意下载内容。

## 保存与重新检查

设置保存在本实例 Electron 用户数据目录的 `sep-updates/update-preferences.json`。可靠保存后才确认新值；保存失败保留旧值。损坏或不可读取的偏好会给出错误并停止发现，不会静默降低过滤强度。

保存成功使未确认的旧检查和旧提示失效，清除过时的可用状态，并重新检查 DSH 与 SEP。迟到的旧响应不能恢复已过滤版本或通过旧弹窗排队。此前已经明确确认并排队的操作仍保留原授权，取消它们须使用现有取消入口。

过滤只决定发现范围。候选尚未适配、缺少可安装包、兼容性未知或有硬阻断时，原有报告、完整性校验、精确计划与用户确认要求继续生效。发现官方新版本不代表 SEP 已经适配完成，也不自动安装。

## Token 与数据

切换过滤不调用模型，不清零账本，不增加额度，也不重置既有消费和预留。若另行打开了“更新适配评估”，更宽的通道可能发现更多 DSH 版本，进而触发该功能已有的评估与预算规则；该开关仍默认关闭。用户插件及其配置保持原有保护范围。
