# Beta.2 离线升级桥安装后源码审查

范围：固定的 Windows x64 离线升级桥，DSH 0.2.0-rc.2，SEP 0.2.1-beta.1 → 0.2.1-beta.2。审查包括 stage / prepare / approval / install / integrity / profiles，以及 operator 的精确文件、配置、依赖、同意校验和复用的原生 P2 发布入口。未重新审查全仓库，也未逐项运行全部用户插件。

## 安装与字节绑定

升级桥的已安装运行文件、D: 构建副本和本仓库工具源码按哈希核对一致：1625 个清单运行文件，另含清单和 bundle-id 共 1627 个绑定输入。清单 SHA-256 为 `ad91a7ee35566a9f03fbd336ee5d5f2652079436edb317983daaaa23cb6533f1`。安装后的可执行核验同时检查 1510 个依赖输入和本地依赖链接。Git 保留原字节，不提交生成的 node_modules 链接。

工具只接受两份固定基图，目标图均为 `96fbacddd11ac56871f1909e1a9f00ccd3669a5a365e8d7061cb8f5cd7ac7143`：公开 Beta.1 基图 `ec39d3b4…` 改 28 个程序文件；已装过滤器的本地 Beta.1 基图 `682529a8…` 改 7 个版本绑定文件。没有放宽旧内置更新器的通用包所有权清单。未知或修改过的基图须拒绝。

## 已定位并修正

1. 风险确认检查缺漏：原复用入口只检查 accepted 和三个指纹，未要求明确接受未逐项验证的兼容性风险。失败测试先复现；现要求 `acceptedCompatibilityRisk === true`，并在持锁复核时再次检查。未签同意的 prepare 不执行发布。
2. 解压后的依赖准备缺失：新增 install.mjs，只重建工具包内清单规定的 junction；已有别名不匹配时拒绝，不重写用户插件别名。
3. 首版打包递归排除 tests，误删被第三方依赖清单绑定的 Zod 文件；干净解压测试复现 ENOENT 后，改为只排除桥根级 tests 的运行清单，依赖自身文件完整保留。源测试仍单独随包交付。

三个修改发生在最终封装与日常计划准备之前；最终包不再使用失败版清单。红/绿日志均保留在本地证据目录。
