# Official LibreOffice runtime: source and redistribution material

This directory contains the official LibreOffice **26.8.0.3**, Windows x64 runtime, from The Document Foundation. Build ID: `bce0998afefdbc355585ca324285661a2170ba77`. The release download is labeled **26.8.0**. It is an independent Office conversion engine used through a command-line adapter; it is not the unavailable `@deepseek-ai/libreoffice-kit` Node API package.

## Binary origin and layout

- Official MSI: https://download.documentfoundation.org/libreoffice/stable/26.8.0/win/x86_64/LibreOffice_26.8.0_Win_x86-64.msi
- SHA-256: `4aa6c6e1895f4055104effcb556bd3362d20c6ad707c149543304f395ef9db95`
- Downloaded size: 374,906,880 bytes. Hash matches the official HTTPS checksum.
- Windows Authenticode verification on 2026-09-21: **Valid**, signer **The Document Foundation**, certificate thumbprint `6480532A562B36D1BFFFC5B5EACF7C31E74E9B28`.
- Extraction used Windows Installer administrative extraction (`/a /qn`), not a global application installation. The extracted administrative MSI database is excluded from this runtime.
- Ten official x64 Microsoft C++ DLLs are copied unchanged from `System64/` into `program/` for application-local use. Original directories are retained. `source-provenance/portable-layout.json` records every copy and hash. Source/binary code was not patched by this layout operation; this is a repackaged layout, not a claim that the entire directory is identical to the MSI.
- `program/soffice.com` is the Windows command-line entry. The caller must supply a unique `-env:UserInstallation=file:///...` profile and its own output/temp directories, and must own and clean up its processes. Set the child process environment `PYTHONDONTWRITEBYTECODE=1` so Python dictionary extensions do not create bytecode inside the program tree. Generated bytecode from initial synthetic validation was excluded from this runtime and retained separately as test evidence.
- Upstream minimum operating-system baseline is Windows 10. This package targets Windows 10/11 x64; runtime behavior on other operating systems is not established here.

For example, download the core archive with `curl.exe -L --fail --output libreoffice-26.8.0.3.tar.xz <the core URL above>`, then use PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath .\libreoffice-26.8.0.3.tar.xz` and compare with this table. `source-provenance/acquire.ps1` contains exact fixed download commands and integrity checks for all four archives and the MSI. Copy that script into a fresh, empty writable directory before running it, so acquisition does not alter an installed package. It will not install anything globally. Its optional `-Extract` mode only creates a new administrative extraction; it refuses to overwrite a runtime.

The core archive contains the preferred source, patch files for external projects, build system and configure scripts. Selected original files are copied unchanged into `source-provenance/`, including `README.md`, `configure.ac`, `download.lst`, `autogen.sh`, and `distro-configs/LibreOfficeWin64.conf`. The source README identifies the official Windows build configuration and links to [Windows build instructions](https://wiki.documentfoundation.org/Development/BuildingOnWSLWindows). The same source is available from the [official core repository](https://git.libreoffice.org/core) at the build ID above.

`download.lst` pins external dependency archives and checksums used by the build system. Build-dependent external archives are obtained by the upstream build/fetch process; they are not all copied into this runtime, and this evidence does not claim that every optional external archive has been downloaded or that the official binary has been locally rebuilt. The four complete source archives are retained with the acquisition evidence and can be delivered separately without increasing every installed runtime by another 654 MB.
