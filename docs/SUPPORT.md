## Office 问题的附加信息

请补充文件格式、合成样本、Windows 版本、文档声明字体及本机字体是否安装、预期／实际页数、错误分类、是否取消或超时，以及 `fontDiagnostics` 状态。注明使用 `20260921-mit-alpha` 和实际包 SHA-256；旧 Kit 报告不能直接套到新 CLI 转换器。禁止公开上传原始私人 Office 文件、包含正文的临时副本和未脱敏系统路径。


请先核对[兼容性和已知限制](COMPATIBILITY_KNOWN_ISSUES.md)，确认报告的是哪个实际程序或安装包。DSH 本体版本相同并不表示 SEP 修订相同。公开反馈入口以**发布者正式发布页指定的渠道**为准；项目仓库为 [GitHub](https://github.com/Lance-QwQ/DSH-SEP)，请使用仓库公布的 Issues 或支持入口，不要求向无关开源项目提交 SEP 问题，也不承诺响应时限。

## 反馈前可以做的检查

1. 记录包的分发修订、程序图 SHA256 和文件校验结果；不要修改版本文字来匹配文档。
2. 记录界面中的完整错误码、发生时间与操作顺序。“关闭窗口”会留后台；需要完整退出时使用应用或托盘退出入口。
3. 模型报错时区分协议/地址、HTTP 分类、输入输出上限与预算状态。超时或未知结果不意味着操作没有执行，不要反复重试有副作用操作。
4. 记忆报错时记录当前项目的自动学习 / 自动引用开关及有限运行状态，不必导出记忆正文。关闭开关不等于删除已有记录。
5. 更新被阻止时保存兼容性报告中的插件名称、版本、原因和候选状态。缺少批准候选或来源基线不能靠“忽略风险”解决；不要手工覆盖程序。
6. 启动或恢复被阻止时，保留状态及错误码。不要先删除锁、治理头、预算账本或事务日志；未知状态应由受控恢复流程核验。

如能在新建合成项目复现，优先提供不含私人内容的最小输入。不要为了诊断移动正在使用的安装目录、覆盖旧快照或按 `node` / `electron` 名称批量结束进程。

## 提供附件前的脱敏

- 不发送 `.env`、真实 API Key、Authorization、Cookie、完整凭据配置、私人记忆库、整份聊天或整个安装目录。
- 把绝对路径改为 `<安装目录>` / `<项目目录>`，把用户名、邮箱、私人仓库、会话和项目 ID 改为稳定占位符。保留必要的相对路径结构、扩展名、字符长度及错误码，便于复现。
- 截图检查侧栏、标题、最近文件、通知和输入框；日志检查工具参数、文档正文与模型返回，不只搜索 `sk-` 前缀。
- 保留软件版本、包哈希、状态转换和时间顺序。脱敏在副本中完成，原始证据留在本机；不要把脱敏后的副本哈希写成原始证据哈希。
- 疑似漏洞或已经泄漏的私人内容走[安全反馈](SECURITY.md)的私密渠道。没有私密渠道时，不公开完整利用步骤或敏感正文。

自动记忆 HTTP 分类有脱敏措施，但本地会话、第三方插件、运行脚本与截图仍可能包含敏感数据。“已脱敏分发包”仅描述交付包，不代表用户日后生成的所有报告都可以公开。
