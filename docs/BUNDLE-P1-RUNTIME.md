- 关闭先禁止本组合的新请求，取消选定项目的原生 Agent，并等待 `whenIdle()`、模型账本 finally、原生工具最终结果和受管任务最终记录。原生压缩行恢复后才关闭 Profile 和 P2。

## 关闭契约与界限

`sepP1Runtime.close()` 默认等待 5000 ms（可配 100–60000 ms）。截止时尚有实际工作则返回 `blocked / draining / resourcesRetained:true`；Session、存储与 P2 继续保留，实际结束后可以再次查询/关闭得到 pass。原生行被用户改变或恢复导入失败时返回 `restore-blocked`，保持保护资源并允许受控修复后重试，不覆盖用户改动。

官方 prepared 模型请求不可变；本片段不会替换请求中的 signal，以免破坏原生调用与预算轮次绑定。显式 `stream(options)` 在进入原生 LLM 前合并生命周期信号，原生 Agent 使用自己的取消接口，压缩使用已审阅组合的取消接口。无法取得取消句柄的其他原生请求只能等待实际结算，不能承诺强制取消。

Fiber 卸载加入实际收尾，可超过上述关闭回执期限；它不等于整个应用的有界关闭。宿主必须负责启动与卸载准入，先使用显式 close 再移除前置服务。没有引入“日常 Agent 任意工具错误都停机”的全局规则。传输失败保留 `status: reserved / phase: unknown`，后续独立工作仍可继续；unknown 不代表免费重试。

本入口仍是显式冷启动片段：现有文件/Session 提供方必须由受信任宿主先按计划退役；须有已治理存储、注册项目、有效账本和普通官方压缩行。先 review，再用返回的 planHash activate；绑定确认仅授权该冷启动片段，不是部署确认。它尚未自动安装完整 SEP 的 RAG、分层记忆、媒体、设置页与外部评测功能。
