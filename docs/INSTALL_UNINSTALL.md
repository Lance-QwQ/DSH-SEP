## Office 运行库与安装空间

Only 和 Full 均包含独立的官方 LibreOffice 26.8.0.3 转换运行库，单这一组件解压后约 **1.58 GB**，整包还另有 DSH、Node、Python 等文件。解压、安装和校验期间需同时容纳来源与新实例，不把 1.58 GB 当作整套安装的磁盘需求。无需安装到系统、注册文档默认打开方式或修改另一 LibreOffice／DSH 实例。

## 选择 Only 或 Full

| 包 | 包含什么 | 安装条件 |
|---|---|---|
| Only | SEP 插件、必要宿主适配文件、第三方依赖和安装运行环境；不含完整 DSH／Electron 载荷 | 提供受支持的 alpha.2 程序根目录。版本、依赖布局及需要复制的文件必须逐文件匹配 |
| Full | 固定的完整 DSH＋SEP 程序图、Electron、Node 和 Python Office 运行环境 | 不要求电脑已有 DSH，安装到新的本地目录 |

两者都**新建增强实例**，不在原官方 DSH 目录里覆盖安装。Only 把校验通过的宿主文件只读复制到新实例，再组合适配内容。相同版本号不代表任意安装布局均支持；匹配失败时选择受支持来源或 Full，不跳过校验。

## 安装步骤

1. 下载同一发行修订的 ZIP、发布说明和 `SHA256SUMS.txt`。在 PowerShell 中计算 ZIP 哈希，与清单对应行逐字核对：

   ```powershell
   Get-FileHash -LiteralPath '.\DSH-SEP-Full-Windows-x64.zip' -Algorithm SHA256
   # Only 则替换为对应 ZIP 文件名。
   ```

   哈希是完整性校验，不是发行者数字签名。校验不符时不要继续。

2. 解压到本地目录。选择一个**尚不存在**的安装目标；目标的父目录应已存在且不是别名路径。建议短路径，例如 `D:\DSH-SEP`。目标不得与解压目录或 Only 的宿主来源目录互相包含。

3. 在解压目录启动 PowerShell，执行 `install.ps1` 并按提示填写。也可使用随包 Node 直接运行：

   ```powershell
   # Full：目标必须尚不存在。
   & '.\runtime\node\node.exe' '.\installer.mjs' 'D:\DSH-SEP'

   # Only：第二个路径是含 node_modules 的受支持宿主程序根。
   & '.\runtime\node\node.exe' '.\installer.mjs' 'D:\DSH-SEP' 'D:\DSH-Host-Program'
   ```

   两条命令选其一，示例路径应按实际情况替换。如果 PowerShell 的本机策略不允许执行脚本，可使用上面的 Node 入口；不需要修改系统全局执行策略。

4. 确认安装输出为 `status: installed`，目标存在 `installed.json`。如果只有 `INSTALLING.json` 而没有成功回执，禁止把它当作已安装实例启动。保留错误及现场，排除原因后换一个新目标目录重装。

5. 用文本编辑器打开安装目录的 `.env`，在 `DEEPSEEK_API_KEY=` 后填入自己的密钥并保存。不要把此文件上传到仓库或反馈工单。空密钥可打开界面，不能完成真实模型请求。

6. 双击安装目录的 `start.vbs`；需要观察启动输出时运行 `start.ps1`。首次进入界面完成设置。不要直接启动程序树里的 Electron 来替代受管启动器。

## 首次检查

- 窗口出现 HARNESS 和 SEP 标识，能进入设置。
- 默认工作区是该新实例的 `workspace`；默认知识来源是其下的 `knowledge`。
- 记忆增强页能显示当前项目及运行状态。只有界面打开不代表外部模型已经可用。
- 配置密钥后，可发送一条简短请求验证模型；这会产生服务方计费。
- 正常退出后再使用相同 `start.vbs` 启动，确认仍进入这个实例。

新安装不带原实例的会话、记忆、密钥或预算记录，也不自动复制用户自装插件。要迁移私人旧库，使用单独审阅的首次纳管流程，不能直接覆盖新库文件。预算按实际部署配置执行；多个实例各有账本不代表可以绕过用户约定的总预算。

## 与官方 DSH 并存

新实例独立拥有程序树、home、数据、Electron user-data、恢复中心、锁、凭据路径、项目身份和动态本机端口。官方实例的程序、插件和快捷方式保持原样；仍通过其原入口启动。

这是**应用实例隔离，不是 Windows Sandbox、虚拟机或全系统权限隔离**。普通 Shell 仍以当前 Windows 用户身份执行。若两个实例主动打开同一工作目录，它们会编辑同一批真实文件，不会自动创建互相隔离的副本。建议分别使用各自工作目录。

## 关闭、完整退出和暂时停用

点窗口右上角关闭会隐藏窗口并保留本实例后台。需要更新、迁移或卸载时，等待当前任务收尾，选择 **“应用 → 退出”**，或托盘的 **“退出 DSH SEP”**。不要按 `node`／`electron` 名称批量结束进程，以免影响官方 DSH 或其他软件。

仅暂停记忆学习或自动召回：在设置的记忆增强页，选择项目并分别关闭对应开关。它不会删除已有记忆，也不等于停用整个 SEP。

暂时停用整个增强实例：正常完整退出，然后继续使用原官方 DSH。当前没有承诺可在受管实例内一键移除所有 SEP 宿主适配并得到原版 DSH。

## 卸载与返回原 DSH

现有分发安装器**没有 `uninstall` 命令**。不要运行臆造的卸载参数。

1. 正常完整退出 SEP，确认没有该实例的活动任务和更新事务。
2. 如需保留资料，先妥善备份实例数据、会话、配置及工作区；`.env` 含密钥，应单独保密保存。工作区备份功能会排除记忆内部域和凭据，不能代替完整实例的数据留存计划。
3. 原官方 DSH 未被安装器原地修改，可使用原快捷方式继续工作。SEP 中新增的数据和会话不会自动出现在官方 DSH 中。
4. 确认资料已经保留、不要再使用该实例后，在资源管理器中核对并删除**该 SEP 安装目标目录**，以及自己创建且明确指向它的快捷方式。不要删除 Only 来源目录、官方 DSH 目录或共用工作目录。

删除实例目录会删除其中的私人数据。只删除程序子目录会留下配置与资料，但留下的目录不构成可启动安装，也不能直接作为安装器的新目标。

## 迁移与更新

安装后的内部 junction 绑定绝对位置，不要直接移动或改名整个安装目录。换位置应重新安装到新目录，再按明确的数据迁移计划处理资料。

最新日常修订支持启动时及运行中每三小时查询官方发布，并提供暂缓选项。实际更新仍要求受控候选、完整性及所有插件兼容检查；风险确认不能越过候选缺失、数据保护或插件保留门禁。历史 r2 ZIP 未含本修复；本次 `20260921-mit-alpha` Alpha 包继承该实现，是否完成包级验证见发布说明。

可选评测及上下文准备入口默认关闭，所需 WSL、Docker、镜像和项目绑定不会由这两份 Windows 安装包自动配置。参见[使用手册](USER_GUIDE.md)与[恢复和故障排查](RECOVERY_TROUBLESHOOTING.md)。
