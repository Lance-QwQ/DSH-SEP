## 本轮实现

- 将 Alpha.1 的 SEP 桌面改动与完整 Alpha.2 官方源码进行三方合并，重新构建 Electron main/preload/welcome、Desktop Host 和 5 个客户端模块。99 个覆盖文件的最终字节由 `tools/alpha2-desktop/SOURCE-FINAL.json` 绑定；没有用旧桌面资源冒充新版本验证。

- 修复真实桌面正常退出时发现的压缩所有权问题：官方 Include 重载会通过 `create=true,force=true` 重放原始 native 行，意外解除 SEP 持有的暂停。现在仅拦截同一父节点、同一 Entry、当前配置仍为原暂停值、重放内容与原行完全相同的情形；直接更新和配置变更仍按官方路径处理。恢复成功后释放拦截器；变更行导致恢复拒绝，不能覆盖用户改动。
- 增加**工具目录内、仅供隔离验证**的受控副本机制。原始日志链不改写、不重算，也不伪造“同目录改名”。显式计划绑定来源/捕获/目标物理身份、日志头、完整前缀、数据指纹和被执行代码。普通 `openControl` 继续拒绝复制件；没有环境开关、模型工具或产品导出可以自动启用该入口，npm 包 files 清单也不包含本工具目录。

## 受控副本的保障与边界

副本验证器在专用组合中重定向 P2 控制器的一条身份解析导入，其他相对导入固定到被测试的原程序；转换表与源/结果哈希随计划保存。原 P2 控制器代码、原存储身份文件、原日志和默认 Profile 入口都不修改。核心仍执行完整日志归约、数据漂移校验及本机独占租约。

初次创建和每次重开都要求来源/冻结捕获仍匹配，目标仍为确认的物理目录，原日志前缀和存储位置证据没有改变。对账失败、缺失删除依据、未完成 intent、维护屏障、链接或篡改均拒绝；不能把未知覆盖状态重置为“空库起点”。合成测试额外证明删除序号及撤回依据保留，不能据此宣称真实私人库曾发生过删除：本次私人日志的删除事件为 0。

只开放读取、三域受管 `put`、合成 Profile、重开和审计。维护、回退、更新、纳管、文档删除和历史备份清理被阻止。历史备份及其旧绝对路径保留在冻结捕获，**不挂载到可操作的副本中**。工作目录、会话、账本、文件恢复目的地、锁和恢复控制根全部使用新目录；Recovery 的显式 memoryKey 将选中的旧记忆作用域绑定到合成工作区，原项目路径不会获得写入许可。该流程使用受信任测试组合，不是通用的任意 JavaScript 沙箱。

这证明受控测试副本能接续，不授权将副本直接作为生产库、不证明生产目录迁移或旧备份恢复安全。副本中新生成正文、暂存及失败现场均位于受保护的 `private-*` 目录。新副本先建立只允许当前用户、SYSTEM、管理员访问的父目录，再复制正文。仅用于本次本地验收，禁止公开；保留至用户复核和明确清理，不自动删除原件，也不承诺不存在期限的自动清理器。
