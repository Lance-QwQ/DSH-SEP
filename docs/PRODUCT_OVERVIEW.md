**记住项目背景，追溯工作依据，让执行与维护更有章法。**

DSH SEP（DEEPSEEK HARNESS SYSTEM ENHANCEMENT PACKAGE，DSH系统增强套件）是一套面向 **Windows x64** 的 DSH 增强组件。它沿用 DeepSeek Harness 的模型接入、对话、工具调用和插件基础，增加可管理的长期记忆、项目知识检索，以及任务、更新和故障恢复流程。

你仍然在熟悉的 DSH 中工作，多了一套帮助项目持续推进的能力。

## 相较于 DSH，SEP 增强了什么？

以下以 DSH `0.1.6-alpha.2` 为基础，列出 SEP 额外接入或适配的功能。原版 DSH 已有的模型、工具、会话和插件能力继续沿用。

| 核心亮点 | SEP 带来的增强 | 对日常工作的价值 |
|---|---|---|
| **让项目拥有可管理的记忆** | 在当前上下文之上加入项目事项、长期偏好与目标、按需历史归档，形成四层记忆。自动学习和自动召回可分别开关；记忆支持更正、撤回和受控删除。 | 把反复需要的背景与习惯保存下来，减少重复交代，也能纠正过时信息。 |
| **让自己的资料成为知识来源** | 为授权的本地文档建立检索库，支持文本、Markdown、CSV、JSON、数字文本 PDF 和 DOCX；检索结果带来源与定位。 | 把项目说明、需求和历史资料接入任务，方便核对回答依据。 |
| **长对话也能回看依据** | 为 DSH 的历史压缩流程增加来源检查、人工审阅和受控原文展开；同项目的允许消息可用于提炼候选记忆。 | 需要追溯细节时，可按需查看来源，帮助延续上下文。 |
| **重要改动先形成候选** | Safe Change 为已有单个 UTF-8 文件提供候选副本、静态检查、差异审阅和确认发布流程。 | 在正式修改前看清将改什么，先发现一部分可检查的问题。 |
| **子任务有明确的执行边界** | 经 `suite_delegate` 创建的只读子任务加入工作前就绪检查、最多两个子任务、最多两次返工，以及超时、取消和执行记录；模型与预算限制另行管理。 | 让分工、执行范围和失败状态更容易掌握。 |
| **遇到故障有恢复路径** | 为登记实例加入有界守护重启、桌面重连，以及检查点和受控恢复入口。 | 在已覆盖故障中帮助恢复连接或工作状态；无法确认安全恢复时给出阻断状态，便于继续处理。 |
| **更新前先看兼容情况** | 启动及每运行三小时查询官方 DSH 发布，提供“立即更新／暂不更新”；列出 SEP 与其他插件的不兼容或未验证项，批准的候选再进入受控更新流程。 | 提前了解版本与插件风险，按保留用户数据、配置和自装插件的规则推进更新。 |

## 它适合怎样的工作？

例如，一个持续维护的软件项目：先把需求文档加入知识库，把项目总目标和输出习惯保存为记忆；后续任务按需引用这些信息，复杂工作交给受管子任务辅助处理。准备修改文件时先审阅候选；需要追溯历史、处理故障或更新宿主时，再进入对应流程。

这些能力主要增强记忆、执行和维护环节。持久记忆保存在模型之外，不修改 DeepSeek 模型权重；模型仍通过 DSH 原有方式接入。

## 保留熟悉的桌面，选择适合的安装形式

记忆增强位于设置页，沿用 DSH 现有工作模式。桌面延续关闭窗口后保留后台的使用方式，并提供 HARNESS / SEP 一体式标识与完整退出入口。

- **Only 增强包**：面向已有受支持 DSH 来源的用户，提供 SEP、必要宿主适配及运行依赖；校验并复制所需本体文件，在新目录建立实例。
- **Full 完整包**：包含 DSH、SEP 和配套运行环境，在新目录建立独立实例。

实例分开管理程序、配置、数据和所属进程，安装不会原地覆盖来源 DSH。它属于应用实例隔离；如果主动共用工作目录，双方仍会接触同一批文件。

## 使用前了解这几点

文件预检只覆盖接入的流程，普通 Shell 不会自动进入隔离试改；静态检查不能代替运行测试。记忆与索引在本地管理，被选入模型请求的内容仍可能发送给模型供应商。自动恢复与更新以可验证条件为前提，未知版本需要适配，插件“未验证”也不会被当成“已兼容”。
