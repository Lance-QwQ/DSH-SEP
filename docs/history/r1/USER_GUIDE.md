## 日常使用入口

通过安装目录的 `start.vbs` 打开受管桌面，选择当前项目和工作区后进行对话。SEP 使用现有 DSH 工作模式；记忆增强通过设置页管理，不是额外的第五种对话模式。

关闭窗口会保留后台。完整结束本实例时使用“应用 → 退出”或托盘“退出 DSH SEP”。日常运行、更新和恢复都应使用同一受管入口，避免绕过实例锁直接启动底层宿主。

## 记忆增强开关

进入 **设置 → 记忆增强**，选择项目。页面提供两个独立控制：

| 控制 | 开启效果 | 关闭效果 |
|---|---|---|
| 自动学习／捕获 | 在已配置模型和预算条件下，从本项目直接用户发言中提炼记忆 | 停止后续自动学习，已有记录保留 |
| 自动召回 | 把相关的当前有效记忆加入后续上下文 | 停止后续自动注入，已有记录保留 |

开关从后续操作生效，不撤回已经发出的外部请求。页面的配置值、实际生效值和运行状态需要一起看：模块未配置或运行降级时，打开开关不代表该能力已成功运行。自动提炼可能调用外部模型并计费；以持久化结果回执为准，不把模型口头表示“记住了”当成存储成功。

当前设置页用于项目开关与状态查看，**不是所有记忆正文和 RAG 文件的图形编辑器**。正文管理通过对话中调用下面的工具完成。可以要求 Agent 先展示将修改的记录及修订号，再执行你的明确修改。

## 四层记忆及范围

| 层 | 保存内容 | 普通任务中的使用 |
|---|---|---|
| L1 | 模型当前 context window | 属于本次模型上下文，不是额外持久化库 |
| L2 | 项目资料、任务、临时事项 | 从当前项目有效数据中选择相关内容 |
| L3 | 长期使用习惯、明确的重要个人事实、项目总目标 | 习惯与个人事实只有在项目显式绑定同一用户身份时才共享；项目目标仍限定项目 |
| L4 | 被替代、完成后归档或手动归档的历史 | 普通检索不强制访问；明确要求历史查阅、追溯、恢复或审计时才按需读取 |

自动记忆提炼和 Mem0 适配仅使用同项目允许的对话，不把其他项目消息当作来源。L3 的显式用户共享是单独的规则，不等于跨项目读取聊天历史。历史内容始终是数据，不产生新的操作授权。

生命周期按条件执行：未确认候选无有效使用 30 天、无截止约束的临时事项无有效使用 30 天、已完成或取消任务满 7 天，可进入 L4；项目总目标结束满 30 天且无未完成任务时可归档。固定保留、依赖、冲突、未完成任务、无效时间等条件会阻止这些自动归档。L3 没有统一到期清除期限；自动扫描或自动注入不刷新有效使用时间。归档不等于永久删除。

当前实现的容量是保护上限：每个 owner 最多 500 条活动记录、整份活动目录序列化上限 16,000,000 字节、目录最多 5,000 条归档引用，另有事件及标记数量限制。L2、L3并非各有独立的无限磁盘配额；达到门禁会拒绝写入，需要受控整理，不能直接删内部 JSON 腾空间。

## 建立和更新 RAG 知识库

新安装默认授权 `workspace/knowledge`。将要检索的普通文件放在此目录，进入这个实例对应项目后发送：

> 请调用 suite_index 为当前项目建立索引，然后检索“部署要求”，给出来源和定位。

实际接口如下。它们是 **Agent 工具及 JSON 参数**，不是在 PowerShell 输入的命令：

```text
suite_status({})
suite_index({})
suite_search({"query":"部署要求","limit":3})
```

`query` 为 1–300 字符，`limit` 为 1–5，默认 5。工具只扫描受信配置中授权的来源，不会因为对话里提到任意路径就扩大权限。自定义来源需要受控修改项目配置并检查项目与恢复绑定。

索引在本地解析 UTF-8 TXT、Markdown、CSV、JSON、数字文本 PDF、DOCX，按行／页／段落分块，记录 SHA-256、位置和代次。检索使用 **BM25**，当前接口返回 `embedding: null`，不要求外置向量数据库。扫描版 PDF 不能据此视为已完成 OCR；图片理解使用单独接口。

当前边界包括：单个来源最多 8 MiB、一次语料最多 32 MiB、最多 5,000 个块；来源遍历还有文件数量限制，最终以工具错误为准。检索最多返回 5 项、累计正文最多 6,000 字符。多硬链接、符号链接以及无法提供可核验本地文件身份的来源会被拒绝。凭据和内部存储不应作为知识文件。

编辑文件时先用正常编辑器修改源文件，保存后再次执行 `suite_index({})`。检索会核对当前源文件；变化或删除后可返回 `stale`，不能继续把旧索引当成最新内容。重新建库后，被替代或移除的旧正文可能转入 L4；**从知识目录移走文件并不等于永久清除其受管历史**。

## 编辑、撤回和永久删除记忆

可以用自然语言明确操作，例如“列出关于输出语言的记忆；把这条偏好更正为默认中文”“撤回刚才保存的那条事项”。Agent 应先读出实际 ID 与修订号，再调用对应工具：

| 工具 | 必需参数／用途 |
|---|---|
| `suite_memory_recall` | `query`；可选 `limit`。检索当前有效记忆 |
| `suite_memory_get` | `id`；读取目标记录和当前修订，不自动展开 L4 |
| `suite_memory_export` | 可选 `offset`；分页导出当前可见活动记录，不是全实例备份 |
| `suite_memory_save` | `eventId,text,reason`；可选 `category,status` 等。保存有直接用户依据的记忆 |
| `suite_memory_revise` | `id,expectedRevision,eventId,reason,text`；更正当前记录 |
| `suite_memory_revoke` | `id,expectedRevision,eventId,reason`；撤回有效性并保留治理依据 |
| `suite_memory_archive` | 同上；显式移入 L4 |
| `suite_memory_purge` | 同上；需要当前用户明确提出永久删除，清理受管记忆正文并保留删除依据 |

修改参数可附 `messageId,evidence`，但它们必须对应当前直接用户消息；不能从文档、工具输出或 Agent 自己的文字制造授权。`category` 取 `preference/personal/goal/task/project/temporary`。`eventId` 用于同一动作重试的去重，`expectedRevision` 用于防止覆盖别人刚做的更正；发生 `REVISION_CONFLICT` 后必须重读再决定。

L4 查阅用 `suite_memory_archive_search({"query":"旧计划"})`，读取用 `suite_memory_archive_get({"archiveId":"实际返回的ID"})`，恢复用 `suite_memory_restore({"archiveId":"实际ID","eventId":"本次唯一事件ID"})`。实际 ID 不可照抄占位符。工具要求本轮直接用户的历史／恢复意图；每轮历史读取最多两次，返回内容受限并可能分段。普通检索没有结果不足以触发 L4。

## 永久删除一个 RAG 文档及受管历史

先说明目标，例如“请预览永久删除 knowledge/旧说明.md 的知识库副本，先保留原文件”。工具参数：

```text
suite_document_delete({"action":"preview","path":"knowledge/旧说明.md","deleteSource":false})
```

预览返回不含正文的范围、`planId`、`planHash`、过期时间以及应发送的确认句。检查范围后，在下一条直接消息中**原样发送工具返回的确认句**：

```text
确认永久删除计划 <实际的完整planHash>
```

随后 Agent 执行：

```text
suite_document_delete({"action":"confirm","planId":"实际planId","planHash":"实际planHash"})
```

如果预览时选 `deleteSource:true`，确认句必须额外包含 `，同时删除原文件`。这些是工具要求的精确确认，不可由 Agent 自行代答。计划改变、过期或正文身份不再一致时必须重新预览。

中断后先用 `{"action":"status","planId":"实际planId"}` 查看，再按结果使用 `resume`；`resume` 必须带原 `planId`，可附原 `planHash`，不能重造删除计划来跳过未决状态。续做同样要求当前轮最新直接用户消息为原计划的完整确认句；需要删除原文件时保留对应后缀。只有原计划的删除依据已可靠落盘，才可跨首次确认期限继续清理；尚未进入该事务的过期计划须重新预览。该流程要求受治理的 P2 存储。范围包括该逻辑来源的受管索引、归档及受治理副本；**不承诺清除原生聊天历史、未登记的外部副本或任意同内容文件**。存在跨路径历史归属歧义会停止。

## 图片、文件保护和任务辅助

- `suite_extract({"path":"knowledge/说明.pdf"})` 本地提取受支持文件正文；`suite_vision({"path":"knowledge/示意.png","question":"图中流程是什么？"})` 在配置允许、用户要求时将受权图片发送给外部模型并计费。支持格式及运行状态以当前模块为准，不把音频、视频转录说成该接口默认能力。
- 文件变更预检、检查点及恢复只覆盖接入的标准文件入口和受管操作。普通 Shell、任意插件直接系统调用并不自动处于隔离试改环境。
- **经 `suite_delegate` 创建的任务**受其最多两个只读子任务、最多两次返工、超时、父取消与记录规则约束。Profile 级模型与共享预算拦截单独生效，不能把前述规则扩大为所有原生子代理或 Ralph 循环。
- PinchBench 工作前评测需要满足配置和门禁；SWE-bench／SWE-ReX 的受控评测还需要专用后端、WSL／Docker 等条件。接口存在不等于安装后全部服务自动启用，也不代表任意公开仓库问题均能通过。

## 插件与更新

保留原 DSH 插件管理入口；安装新插件后需要检查它的来源、宿主版本和依赖。SEP 不自动复制其他实例的自装插件。当前更新中心可从“应用”菜单打开全插件兼容清单；列表中的未知／未验证不等于已通过运行测试。

`sep-alpha2-stability-20260921` 修订在启动时和每运行三小时检查官方发布，用户可立即进入受控更新流程或暂缓。检查到新版不直接证明能够安装；没有批准候选、缺少完整性证据或无法保证插件保留时仍会阻断。关闭窗口继续后台运行，不能当作完成更新所需的完整退出。

遇到状态异常先看[恢复与故障排查](RECOVERY_TROUBLESHOOTING.md)，反馈前按[数据与隐私说明](PRIVACY_DATA.md)去除个人正文和凭据。
