## 先保留哪些信息

记录触发时间、DSH 与 SEP 修订、具体错误码、当时操作、是否存在未完成任务及最近更新情况。保留失败现场，不先删除锁、重置库或覆盖配置。

可以提供已经脱敏的错误码、操作回执和版本哈希。不要提交 `.env`、原始会话／记忆正文、带 token 的本地恢复 URL、完整连接文件、私人路径或整个 `home`／`data`／`state` 目录。未知结果尤其需要保留原任务 ID、事务 ID 和请求 ID。

## 三种恢复不能混用

| 类型 | 用途 | 不提供什么 |
|---|---|---|
| 宿主监督和桌面重连 | 观察所属宿主退出，有界重启；界面重新认证新代次连接 | 不自动重放模型或外部工具操作，不保证假死／硬件故障后无损恢复 |
| 工作区备份 | 用户明确创建文件备份，核验后恢复到一个全新的目录 | 排除凭据、依赖、SEP 内部记忆域；不是任意并发写者下的数据库一致性快照 |
| P2 更新／纳管事务恢复 | 按提交记录、同代数据及兼容证据处理受控发布中断 | 不能因有旧备份就覆盖发布后产生的新业务数据，也不能直接把私人旧库当空库初始化 |

原版 DSH 的返回方法也单独区分：Only／Full 安装到新目录，原官方 DSH 未被覆盖，使用其原快捷方式即可返回；这不等于把 SEP 新产生的数据自动迁回原版。

## 宿主退出、界面失联或工作区丢失

1. 暂停重复点击和重复提交。查看界面显示的是恢复中、暂停、失败，还是操作结果未知。
2. 最新修订会清除旧连接并验证新宿主身份后重连，桌面自动等待上限为 **60 秒**。超过期限、身份不匹配或守护熔断会停止等待，不伪装成恢复成功。固定测试中的数秒恢复不是所有机器的时限承诺。
3. 默认守护预算为 **10 分钟内最多自动重启 2 次**；手动停止不会被当作崩溃重启。这个次数与经 `suite_delegate` 创建任务的返工上限分别计算。
4. 若工作区被移动、删除或同路径替换，恢复中心应暂停该项目；不要建一个同名空目录冒充原身份。通过恢复中心先预览重绑定，审阅新目录及计划，再明确确认。项目 ID 和记忆命名空间需要保持受控关联。
5. 任务中断后，先审阅操作回执并核对未知的外部效果。受控续接创建新的关联会话，不自动复制原对话正文、请求模型或重放工具。

监督主要覆盖进程退出和启动就绪超时，并非运行中所有假死的心跳监控。磁盘硬件故障、从未备份且已丢失的文件、系统故障、原生组件致命错误，以及无法确认归属的外部进程均不保证自动恢复。

## 常见错误

| 现象／错误码 | 含义与下一步 |
|---|---|
| `HOST_VERSION_UNSUPPORTED`、`HOST_PACKAGE_AMBIGUOUS`、`CONTENT_CHANGED` | Only 来源不在当前固定支持范围，或字节与清单不一致。核对包及来源；选受支持来源或 Full。不要改清单哈希来绕过 |
| `DESTINATION_EXISTS`、`DESTINATION_OVERLAP`、`DESTINATION_ALIAS` | 安装目标已存在、与来源重叠或路径带别名。使用新的明确本地目标，不把现有私人目录当作待清理目标 |
| `PROVIDER_HTTP_401_AUTHENTICATION`、`PROVIDER_HTTP_403_FORBIDDEN` | 服务端认证或权限拒绝。私下核对自己的 key、服务地址与账户权限，不把 key 发给反馈人员 |
| `PROVIDER_HTTP_402_PAYMENT_REQUIRED`、`PROVIDER_HTTP_429_RATE_LIMIT` | 账户计费／额度或速率限制。先检查服务方账户和限流条件；不要无界重试 |
| `PROVIDER_HTTP_503_SERVICE_UNAVAILABLE` 等 5xx | 上游服务失败。分类改进不能消除上游故障；记录并稍后决定是否重新发起，失败提炼不会自动重放 |
| 只有 `PROVIDER_HTTP` | 缺少可用 HTTP 分类元数据，或使用旧修订。保留该错误，不猜测它一定是 503 |
| `PROVIDER_FAILED`、请求超时／连接中断 | 结果可能未知；外部服务可能已执行并计费。先核对回执、服务记录和预算预留，不默认“失败所以未执行” |
| `P1_INPUT_LIMIT` | 送往 Profile 的请求 UTF-8 字节数超限，不等于模型 token 上下文超限或本机内存耗尽。压缩会话、减少工具返回正文或拆分任务，检查实际配置上限 |
| 输出被截断 | 查看响应结束原因与实际输出上限。当前修订已分离主请求／子任务限制，但仍有保护上限；明确继续范围后再续写，不把截断视为已完成 |
| `BUDGET_LOCKED`、预算锁无法核验 | 不一定是活动进程，也不能直接按 PID 不存在删锁。当前修订可恢复可证明死亡的预算持有者；空锁、破损锁或未知归属仍保守停写，交由维护检查 |
| `RECOVERY_UNAVAILABLE` | 恢复服务或绑定不可用。确认从受管启动器启动、版本与配置一致；不要停用恢复保护以强行读写 |
| `RECOVERY_PROJECT_PAUSED`、`RECOVERY_STALE_CONTEXT` | 项目目录身份失效，或会话使用旧代次。核对真实目录，通过受控重绑定／新任务恢复，不能手改身份绕过 |
| `P2_COVERAGE_UNKNOWN` | 缺少治理覆盖证据，不能证明旧库全部写者及删除历史。停止普通更新；使用单独的首次纳管计划，不对非空旧库执行 `init` 伪造新基线 |
| `RECOVERY_MAINTENANCE_REQUIRED` | 当前入口不能安全执行维护。按对应受控维护流程结束写入并处理，不能单独运行底层发布命令绕过 |
| `P2_ADOPTION_CAPTURE_HELPER` 或更具体的捕获错误 | 先看失败阶段与错误分类。最新修订已处理 PowerShell 5.1 长路径和 UTF-8 问题，但权限、链接和身份不可核验仍可能合理拒绝；历史 r2 ZIP 未含本修复；本次候选的验证状态见发布说明 |
| `UNAUTHORIZED`、`SOURCE_CHANGED` | 来源未授权、存在多硬链接／符号链接或本地身份变化。检查文件和来源配置，必要时放入正常单链接文件再重新索引 |
| RAG 返回 `not_indexed`／`stale` | 未建索引或源文件／解析器已变化。调用 `suite_index({})` 后再查询 |
| `REVISION_CONFLICT`、`DOCUMENT_PLAN_CHANGED` | 记忆修订或删除计划与现状不同。重新读取／预览并审阅，不能改成新修订号后盲目提交 |
| `DOCUMENT_HISTORY_IDENTITY_UNKNOWN` | 跨路径历史归属不明确，当前删除计划无法证明完整范围。保持停止，核对副本来源；不要猜测删除所有相同正文 |
| `MEMORY_LIMIT`、`MEMORY_CATALOG_LIMIT`、`ARCHIVE_LIMIT` 等 | 已达到容量保护门禁。先导出／审阅与受控归档、永久删除，不能直接编辑内部数据文件 |
| 更新弹窗空白／跳转无页面 | alpha.2 迁移中的旧缺陷已在最新日常修订修复。先核对图和发行修订；旧 ZIP 不会因文档更新自动获得代码修复 |

服务方 404 还应检查所选协议与地址模板是否匹配；本组合的 Messages 适配已修正为相应 `/anthropic` 路径。不要只为消除错误而把不同协议的 URL 任意拼接。

## 使用恢复中心与 CLI

受管实例已启动自己的恢复中心时，不要再用 `serve` 建第二个同目录所有者。优先使用现有恢复页；维护人员可使用随包 CLI。以下是实存入口，变量必须来自**本实例**配置或其受信启动输出：

```powershell
$SepRoot = 'D:\DSH-SEP'
$RecoveryCli = Join-Path $SepRoot 'program\node_modules\@deepseek-ai\dsh-recovery\bin\recovery.mjs'
$ConnectionFile = 'D:\已确认的本实例控制目录\connection.json'

# 查询实际状态；不要把上面的占位连接路径直接作为真实路径。
& (Join-Path $SepRoot 'runtime\node\node.exe') $RecoveryCli call $ConnectionFile status

# 仅在本机查看含管理凭据的恢复页地址；不要转发该输出。
& (Join-Path $SepRoot 'runtime\node\node.exe') $RecoveryCli open-url $ConnectionFile
```

CLI 通用格式为 `call <connection.json> <method> [params.json]`；有参数时提供实际、绝对路径的 JSON 文件。`planRebind/commitRebind`、`planRestore/restoreBackup` 等都先预览、再提交刚审阅计划的实际 `planId` 和 `confirmationHash`。本指南不提供虚构通用计划，也不建议手写确认哈希。

CLI 普通调用超时上限为 5 秒；备份、恢复、续接和启动／停止等长操作上限为 5 分钟。**客户端超时不会自动取消服务端已接收操作**。出现 `blocked`／`execution: unknown` 时，先用状态、备份清单及操作回执确认，不能直接重复恢复或另造请求 ID。含私人路径的查询输出对外分享前仍需脱敏。

## 工作区备份与恢复

备份是明确请求触发，不自动扫描所有私人目录。默认上限为 10,000 个复制文件、单文件 64 MiB、总正文 512 MiB；不包含凭据、依赖和 SEP 私有记忆域。原文件的 ACL、ADS、时间戳等属性不承诺一并恢复。

捕获前暂停会修改项目的所有写者。逐文件核验身份不能替代跨文件事务快照；多进程同时修改数据库时，不应按成功复制文件推断业务一致。

恢复只发布到已审阅且尚不存在的新目录，不合并或覆盖原工作区。完成回执丢失时可能已经产生目标目录，应核对目标和操作记录；不要把它删除后立即重试。备份与失败暂存有自己的清单和按计划确认的删除入口，不能用广泛递归清理替代。

最新修订同时排除新旧 SEP 锁文件名。普通备份不自动识别所有正文中的秘密，不替代隐私检查。此类工作区备份默认不自动过期，应在审阅目录和空间后通过受控入口清理。

## 更新失败与旧快照恢复

P2 的 `committed` 不是“新进程曾启动过”：需要三个数据域发布完成、目标健康检查通过、提交记录可靠落盘，随后才开放业务写入。健康检查已通过但提交记录未落盘的崩溃仍是未决事务，重启后要按持久日志完成判定。

自动恢复旧代码、配置和同代数据至少要求明确兼容性检查、完整且可核验的同代快照，以及覆盖所有受管写者的持久记录证明没有新业务写入。迁移、健康检查、业务写入和审计记录分别判断；不能仅凭 schema 数字相同或“时间很短”推断安全。

删除依据独立于可回退快照；恢复必须重放不会随旧快照回退的删除／撤回依据。依据缺失、损坏、存储身份变化、未知写者或已有新业务写入时，应停止恢复，等待审阅后的处理。恢复旧代码也可能保持维护停写，不能据此宣布原业务已经正常恢复。

现有私人旧库首次纳管是单独流程：核验源库捕获、已知旧入口退役、正文审阅、生命周期保留、发布及首个恢复基线。不能把这项受控功能等同于任意私人库都能直接导入；开启退役可能持续改变原入口权限，取消不一定自动还原，执行前必须审阅具体影响。

## 何时停止自动操作

无法核验身份、删除依据、业务写入序号、提交状态、进程归属或外部执行结果时，保留 `blocked/unknown` 比盲目重试更准确。记录当前代码和现场，正常退出可以退出的自有入口；不要批量杀进程、删锁或覆盖存储。具体恢复方案应绑定实际实例、明确范围及审阅过的计划。
