## 受控流程

1. 查询发布信息，校验清单来源、digest、包 SHA-256 和可接受的安装范围。发现新版不等于存在适配候选。
2. 准备独立候选；盘点全部登记组件与插件实例，保留确认不兼容和运行未验证条目。模型适配评估不能代替这项报告。
3. 用户审阅并确认确切计划，绑定 plan、report、graph。变化后旧确认失效。
4. 等待所属应用正常退出并取得锁；再次核对包、配置、程序、数据代次和路径指纹。
5. 在维护停写下发布。所有要求的数据域发布完成、目标健康检查通过且提交决策可靠落盘后才开放业务写入。
6. 验证实际桌面／Host，记录结果；结果未知不得直接重复切换。

用户可接受列明的运行兼容性 unknown 风险，不能跳过来源、完整性、插件保留、治理覆盖、恢复依据、硬阻断或提交条件。用户自装插件 不通过静默删除／覆盖／禁用来获得通过。

## 数据与回退

消费、未知预留、会话设置、用户插件和受管数据保留。回退必须经明确代码／配置／数据语义兼容性检查；不只看 schema 号。新业务写入发生后，不自动用旧数据快照覆盖。删除依据不随旧快照回退，依据缺失或无法核验时停止恢复。

更新材料可能含私人路径和内联设置，是本地私有恢复资料，不上传发布。未决事务必须保留；本版不宣称全部准备／取消目录都有 TTL 自动清理。关闭窗口只隐藏后台，应用或托盘“退出 DSH SEP”才满足停写条件。
