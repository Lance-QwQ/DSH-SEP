## Office 转换安全边界

转换器仅通过列明输入入口做文件身份、大小、格式和 OOXML 预检；宏执行使用专属 LibreOffice profile 禁用。关系 XML 使用严格解析与白名单，仅标准 hyperlink 的 http／https／mailto 普通链接可保留；外部图片、模板、OLE、data、UNC、file、javascript、DTD／实体及畸形关系 XML 拒绝。Writer／Calc 外链更新配置依据实际版本 schema 设置。普通链接正负对照与回环请求检测沿用 office-r2 固定样本的验证结果，见测试摘要。旧二进制文档不会因此获得完整内部内容审计。

Windows Job、独立 profile、受控临时目录及有界日志用于所属进程收尾和减少实例干扰，**不是恶意文档的操作系统安全沙箱**。没有为原生引擎声明全面的文件／网络拒绝策略，也不保证未知解码器漏洞不会发生。报告请提供脱敏的最小合成样本，不把含私人正文或凭据的原文件直接贴到公开 issue。


本文说明 DSH SEP Windows 适配版的现有机制和反馈方式，不新增安全认证、服务承诺或漏洞奖励政策。当前版本与包状态见[兼容性和已知限制](COMPATIBILITY_KNOWN_ISSUES.md)。

## 已有保护及适用范围

- 标准文件入口提供范围、身份、版本及恢复副本检查；Safe Change 另提供单文件候选验证、审阅和精确确认。普通 Shell、插件直接文件 API 及用户外部程序不因此受到统一沙箱限制。
- 受管记忆按照项目、显式档案绑定、来源和状态决定访问；RAG 拒绝多链接或身份无法核验的来源。它不隔离同一 Windows 用户可执行的恶意程序，也不是多用户账号权限系统。
- 安装和受控更新核验实际文件、包图、候选、插件保留、维护与恢复依据。SHA256 用于完整性比对，不等于发布者数字签名；本机签名记录不是对恶意同用户代码的隔离边界。
- 守护和恢复通过实例、代次与进程身份约束收尾，不按通用进程名清理；结果未知的业务操作不得自动重放。身份或恢复依据不充分时保守阻断，不保证所有故障均自动修复。
- 受控评测使用专门后端与生命周期管理，默认不启用。其容器约束不等于能够抵御所有 Docker、WSL 或内核漏洞。

使用不可信插件或仓库前，应检查来源、所需权限、网络行为与实际配置。模型读取的网页、文件和工具结果可能包含不可信指令；不能把其中的授权文字当作直接用户确认。

## 发现疑似漏洞后

先停止触发问题的任务并保留最小证据，避免继续对真实私人资料反复试验。若怀疑密钥暴露，应在密钥供应商处撤销或轮换，并移除公开副本；不要把完整密钥发给维护者来证明泄漏。

**含利用细节、凭据、私人内容或未公开安全影响的报告，应通过发布者在正式发布页指定的私密渠道提交。** 项目仓库为 [GitHub](https://github.com/Lance-QwQ/DSH-SEP)，私密渠道以该仓库 Security 政策实际启用的入口为准；本文不虚构独立邮箱、响应时限或奖励计划。若发布页没有私密渠道，先发送不含漏洞细节的联络请求，取得私密渠道后再提供完整材料。不要在公开 issue、群聊或第三方项目仓库直接贴出这些内容。

建议报告包括：

1. 受影响的 Only / Full / 日常修订、DSH 版本、程序图及安装包哈希。
2. Windows 环境、启用插件、权限和配置前提，均用占位符替代个人标识。
3. 预期边界、实际越界行为、最小合成复现步骤及影响范围。
4. 是否已经造成数据修改或外部发送；不确定时明确写“未知”。
5. 脱敏日志、截图、时间与错误码；完整 PoC 仅交给指定私密渠道。

维护者尚未核验前，请称为“疑似问题”，不要把某次后续通过视为原问题已修复。普通功能故障使用[问题反馈指南](SUPPORT.md)；数据处理边界见[数据与隐私说明](PRIVACY_DATA.md)。
