# 技术概览 · 0.2.1-beta.1

对应 **DSH SEP 0.2.1-beta.1 / DSH 0.2.0-rc.2 / Windows x64 Beta**。本文描述本版实际实现，不将参考组件、可选后端或未来方案写成已启用能力。[导航](DOCS_INDEX.md) · [用法](USER_GUIDE.md) · [数据与隐私](PRIVACY_DATA.md)

## 1. 插件组合与宿主接口

SEP由多个Cordis插件及必要宿主适配组成，依靠服务注入接入工具、模型请求、会话事件、存储、设置页及桌面生命周期。套件版本与子包local.*版本分别记录；目录里有代码不等于已接线或已启用。Full与Only创建独立实例，分开程序、数据、锁、身份与端口；普通Shell和同进程插件仍拥有实际进程权限，独立实例不是操作系统安全沙箱。

## 2. 本地RAG的建库流程

`授权来源 → 核验本地文件身份 → 解析与分块 → 保存文本/定位/来源哈希 → 查询时分词和BM25评分 → 返回有界片段`。

默认初始来源为获准的knowledge目录，新注册项目须另授来源。文件按行、页或段落生成片段；块ID由路径、文件SHA-256与块序号派生。现有索引保存解析器版本、代次、来源哈希、正文分块和定位，不是训练模型，也没有持久化向量索引。

每次检索重新核对授权和来源SHA-256；解析器版本或来源字节变化返回stale，需要重新建库。正文和定位用于可追溯引用，不把来源内容升级为可信指令。当前实现按查询在内存中分词并计算各候选块的分数，没有持久化倒排索引或大规模检索吞吐保证。

单来源8 MiB、一次语料32 MiB、最多5000块；每块文本最多1200字符。`suite_search`上限5条，正文累计最多6000字符，实际可能少于请求数。符号链接、多硬链接和无法提供可核验身份的来源拒绝。PDF文本提取不等于OCR。

## 3. BM25排序与中文分词

BM25是基于词项匹配的统计排序。TF表示词项在某块内出现的次数，DF表示候选块中含该词的块数，IDF降低常见词影响；长度归一化减轻长文本因词多而占优。本版采用：

```text
IDF(t) = ln(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
score(d,q) = Σ IDF(t) × TF(t,d) × (k1 + 1)
                  / [TF(t,d) + k1 × (1 - b + b × len(d)/max(avgLen,1))]
k1 = 1.2，b = 0.75
```

查询词先去重，零分结果不返回；按分数降序，同分按ID排序，返回分数保留6位小数。N和avgLen来自本次允许参与评分的候选文本，分数只表示该候选集内的词项相关性，不是概率、事实可信度或跨查询可比较的质量等级。

基础分词把汉字拆为单字，并添加从抽取汉字序列生成的相邻双字组合；字母和数字按连续词项处理并转为小写。查询含汉字时，再合并NFKC规范化后的`Intl.Segmenter(['zh','en'])`词项并去重。由于双字组合来自抽取后的汉字序列，它可能跨过原标点或非汉字间隔，不能把它描述为严格语言学分词。源码中有trigram函数，但当前RAG查询没有使用该函数。

返回`retrieval:'bm25'`、`embedding:null`。本地检索不调用Embedding服务，也不要求Mem0云或外置向量数据库；同义改写、隐含意图和跨语言语义匹配可能漏检，宜使用资料中的关键词。进入模型上下文的片段仍按配置发送给模型并计入请求费用。

## 4. 四层记忆及注入

| 层级 | 实际性质 |
|---|---|
| L1 | 模型自身上下文窗口；SEP没有为它再建一个持久化库，也不修改模型权重。 |
| L2 | 本项目资料、任务、临时事项。文档分块与结构化记忆是不同数据对象，不能将全部文档都称为500条记忆。 |
| L3 | 习惯、重要事实、项目总目标。习惯与个人事实只在明确同用户共享配置下跨项目可见，项目目标仍按项目。 |
| L4 | 正文归档与历史修订；普通召回不强制检索。明确历史/追溯/恢复需求才按获准范围访问，查到历史不等于自动恢复为有效记忆。 |

结构化记忆含ID、修订、来源、状态、作用域及生命周期时间。活动召回先过滤作用域和状态，再用BM25排序；自动注入还保留有限的活动目标与习惯优先项，去重并限制条数与上下文字符。因此BM25不是所有记忆决策的唯一依据。

Mem0适配复用固定提炼提示词和schema，只选择当前注册项目、当前会话当前轮次的直接用户消息。模型提炼可能收费；不读取其他项目聊天，也未安装Mem0 SDK、云服务或向量数据库。推断、冲突与明确陈述按实际确认状态保存；候选内容不能只因被模型提炼就视为事实。

## 5. 持久化、容量与生命周期

本版受管组合使用宿主JsonStorageBackend，不将所有记忆都存入SQLite。主要数据域为：

| 域名 | 内容 |
|---|---|
| `dsh_enhancement_suite_v1` | 项目索引、兼容记忆、工作流记录和有界媒体缓存。 |
| `dsh_four_layer_memory_v1` | 活动L2/L3目录、作用域、标记、归档引用及治理记录。 |
| `dsh_four_layer_archive_v1` | L4正文、历史归档和受管备份。 |

域由宿主storageDomain接口读写，受P2共享访问队列、所有者租约及写入屏障约束；当前受管适配核验JSON后端与真实路径。lossless-claw选定模块和适配评估等辅助组件可使用各自SQLite，不能将其数据库等同于RAG主库。

活动目录每owner最多500条记录，整个目录JSON受16,000,000字节限额约束；单条正文最多2000字符。L2与L3不是各自另有独立500条配额。L4按需读取另有窗口限制：最多64个选定归档、扫描256000字符、BM25返回最多2条，再限制输出大小；这些读取限额不等于归档存储的总容量上限。不能宣称L4无限容量。

生命周期依据有效时间、状态、依赖和保留标记：完成或取消任务达到7天、未确认候选和无有效使用临时事项通常达到30天、结束目标达到30天且无未结任务时可归档。置顶、保留、依赖、冲突、非法时间等阻止归档。普通扫描和自动注入不刷新活跃时间；归档先可靠保存正文再移除活动引用。归档保留正文，撤回影响有效性，永久删除按治理计划处理副本，三者不同。

不要直接手工改内部JSON或SQLite。更正使用修订工具；文档先编辑获准源文件后重新索引。永久删除保留独立删除依据，恢复旧快照也必须执行这些依据；依据缺失或无法核验时停止恢复。供应商、外部导出及原生聊天不属于本地记忆删除的全局擦除范围。

## 6. 其他基础机制

- 预算账本区分共享累计、可信根轮次及其子任务额度、会话累计上限；默认会话100元、默认任务5元分别生效。消费和未知预留不因重启、设置调整或重新打开窗口清零。它是本地上界估计，不是DeepSeek充值余额。
- 经`suite_delegate`创建的任务受最多两个只读子任务、两次返工和统一取消记录约束；不能扩大为所有原生子代理或Shell进程。
- Worker使用独立线程和明确取消/截止协议保护部分长操作，不能提供恶意代码的操作系统隔离。外部操作超时后可能已执行，未知点击或请求不盲目重复。
- DSH/SEP发布查询不请求模型；可选更新适配评估默认关闭，开启后分析与复核可能计费。模型报告仍不具安装资格。
- 更新确认绑定包、配置、报告和程序图指纹；锁内重验。三个数据域及程序配置发布、目标健康和可靠提交满足契约后才开放业务。新业务写入后不自动用旧数据快照覆盖。
