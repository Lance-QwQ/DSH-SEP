# Alpha.2 私人副本与真实桌面同次闭环

2026-10-12。本轮在 Windows x64 隔离环境完成了两次真实桌面闭环；没有切换日常版、写入原库或上传 GitHub。DSH 固定为官方 0.2.1-alpha.2；SEP 仍基于 bundle.24 的独立 Alpha.2 派生候选，内部包标识为 `0.2.1-beta.3-alpha2-adapter.1`，不是新的公开 Release 或 RC。

## 实际结果

- 同一份受控私人副本、受管启动器、真实 Desktop Host 和**未修改的生产 Electron `lib/main.js`**共同运行；没有用外置 Electron bootstrap 代替本次默认入口。
- 两轮均实际观察到主界面及旧会话列表。关闭窗口后 Electron/宿主继续运行；真正启动第二个 Electron 可执行进程后，恢复同一原生窗口。应用菜单正常退出后，Electron 和宿主退出码均为 0，未强制清理成功轮次。
- 同一宿主执行旧记忆读取、正文 SHA 与生命周期字段核对、合成记忆写入、受管文件写入、会话读取和账本检查。第二轮完整冷启动后，第一轮新写的合成记忆可读取。19 个旧逻辑会话的 21 个原始文件在每次关闭后保持原字节，1447 条原账本历史保留；没有调用模型流或真实 API。
- 最终只读复核：752 个原库文件的身份、内容及文件集不变；冻结捕获件不变；日常两份入口指纹不变；r5 的 21818 个程序文件保持原字节。
- 最终 ACL/资源审计验证 13846 个条目，仅当前用户、SYSTEM、管理员；本阶段命令行所属进程 0、私人 P2 owner.lock 0。不是全系统句柄或端口审计。

旧会话读取及记忆正文核验由本次同一 Desktop Host 的受信任测试插件执行；主界面只观察列表，不逐条打开私人正文。不得将本结论写成真实付费长任务续跑、所有旧工作区文件恢复或所有插件功能通过。

## 新增验证工具与失败记录

`verification-copy.mjs` 在上一轮测试专用机制上增加只读 `verificationIdentity`：计划哈希、物理目录身份、实现与原控制器哈希、源库/冻结捕获件及原日志前缀均需匹配；不获取第二把 P2 租约、不开放生产纳管或恢复。原生产 P2 的复制件拒绝机制保持不变。身份桥接与原隔离规则共 8 项合成回归通过，新增两个测试先观察到缺失行为再实现。

桌面 r1 在启动前因载具沿用无界面恢复管理器而争用恢复租约，已改用现有受管恢复客户端；r2 的观测插件缺少 Cordis inject 声明，已补齐。两次失败保留原结果、日志及修前载具，属于测试组合修正，未修改生产 r5。r3 的两轮才是成功闭环。

Electron 在 Cache、Network、Shared Dictionary 三处主动加入 Chromium 沙箱能力 SID。测试退出后，仅撤销本轮复制件这三处额外显式规则，随后严格 ACL 审计通过；原库权限未改变。零进程回执是在正常应用/宿主退出、测试控制进程剩余有界截止计时器自然结束后取得，不将失败样本的清理归为成功退出。
